# 日志与诊断规范

本文件规定日志的分档、新增日志的取舍与格式约定，是新增日志时的第一依据。
实现见 `src/shared/diagnostics.ts`（前端）与 `src-tauri/src/app/diagnostics.rs`（原生端）；
系统级描述见 `architecture/overview.md`。

## 两档模型

| 档位 | 内容 | 默认 | 开销 |
| --- | --- | --- | --- |
| 常规 | 事件驱动 + 阈值触发 | 常开 | 可忽略 |
| 诊断 | 周期性探针 + 取证通道 | 发布版关闭、调试版开启 | 有持续开销 |

- **常规档**：发布构建 `info`、调试构建 `debug`。包含生命周期与状态变更、`warn`/`error`、
  未捕获异常、GPU 设备健康，以及阈值触发的慢步骤与长任务。这些记录事件驱动、平时零噪声，
  因此常开，用于捕捉偶发事件。
- **诊断档**：设置页「调试 → 详细日志」开关，等级至少 `debug`。追加周期性探针与取证通道
  （面包屑、独立线程取证 Worker、原生看门狗）。探针只在异常时写日志：主线程心跳每 2 秒刷新
  取证通道但不写日志，事件循环延迟探针与长任务观察器仅在超过阈值时记录。这些有持续开销，
  只在排查问题时启用。
- **追踪档**：`LILITH_LOG_LEVEL=trace`，不进设置页。用于框架内部与更细的细节。

等级由 `app::diagnostics::apply_level`（`log::set_max_level`）统一控制；`LILITH_LOG_LEVEL`
设基线，可升可降；诊断模式开启时至少 `debug`，关闭时取基线。

## 新增一条日志时怎么判断

按顺序回答，命中即定档：

1. **事件驱动还是周期性？** 一次状态变化写一条 → 常规档，直接 `diagnosticsLog("info", …)` /
   `log::info!`。按时间或帧反复触发 → 诊断档，用 `if enabled` 门控或只在 `syncActivity(true)`
   时启停。
2. **是否只在超过阈值时才需要？** → 用 `diagnosticsSlowStep` 或 `log::warn!` + 阈值判断，常开。
3. **是否是失败或异常？** → `warn` / `error`，始终写，与档位无关。
4. **是否属于取证（主线程冻结后仍需留存）？** → 只能走取证通道（面包屑 / Worker / 看门狗），
   且只在诊断档启用；不得依赖同一条 IPC 通道。
5. **是否在高频路径（逐帧、逐指针、逐项）？** → 禁止逐次写，改为阈值、采样或按批汇总。

## 性能准则

- 被等级过滤的 `log::debug!` 几乎零成本（先判 `max_level`，不格式化），可放心埋点。
- 真正贵的是字符串格式化与落盘 I/O；前端还多一次 IPC。因此高频路径禁止逐次写。
- 常规档不得引入周期性定时器，也不得在每帧或每次指针事件中分配日志字符串。
- 前端 `diagnosticsLog` 每次调用都会走一次 IPC，只在事件驱动路径使用。

## 格式约定

- 消息用 `key=value` 字段，字段名稳定、可解析（如 `boardId=`、`gpuSeq=`、`elapsedMs=`）。
- 带上可关联的标识（会话、画板、图片、设备序号），便于把多行串成一次流程。
- 单行、无换行，不打印整个对象。
- 不写隐私内容；路径仅用于诊断，且只在诊断相关日志中出现。

## 索引与筛选

每行日志的固定前缀为 `时间[run:xxxxxx][等级][target]`，消息内可再带一个方括号标签：

- **运行标识** `[run:xxxxxx]`：同一次运行的每一行都相同，用于从按大小轮转的文件里切出单次运行
  （例如 `grep '\[run:3f9a12\]'`）。
- **target**：Rust 侧是模块路径（如 `lilith_artworks::pin_board`）；前端统一为 `webview`。
- **等级**：`ERROR` / `WARN` / `INFO` / `DEBUG` / `TRACE`。
- **标签**：写在消息开头，与等级正交，用于按类别筛选。

| 标签 | 含义 | 何时出现 |
| --- | --- | --- |
| `[hb]` | 主线程心跳迟到 | 仅当心跳间隔明显超出 |
| `[lag]` | 事件循环延迟 | 仅当回调明显迟到 |
| `[task]` | 长任务 | 仅当单次占用主线程超过阈值 |
| `[slow]` | 慢步骤 / 慢读 / 锁等待 | 仅当超过阈值 |
| `[forensic]` | 取证通道（面包屑、Worker 回读） | 启动回读或检测到停顿 |
| `[watchdog]` | 原生看门狗 | 前端主线程停摆 |
| `[gpu]` | GPU 设备丢失 / 未捕获错误 | 发生即记录 |
| `[error]` | 全局未捕获异常 / 资源加载失败 | 发生即记录 |

- 关注事件流时排除探针噪声：`grep -vE '\[(hb|lag|task)\]'`。
- 关注异常时：`grep -E '\[(slow|forensic|watchdog|gpu|error)\]'`。
- 新增日志时，若属于周期性或异常探针，必须复用已有标签；事件类记录不加标签。
