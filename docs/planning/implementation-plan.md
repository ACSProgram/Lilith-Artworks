# Lilith Artworks 分阶段实施计划

更新日期：2026-08-13

## 总目标

把 LilithClient 的自动备份能力和 Proven 的 C2PA/TrustMark 能力整合为一个作品管理应用。应用以可任意嵌套的分组树组织 Artwork；Artwork 是树的叶节点，每个 Artwork 内部拥有可 fork 的备份历史。每个分支绑定独立工作文件路径，可发布一份最终成品并记录认证信息。

## 强制执行约束

- 每次只推进一个阶段；阶段达到下列验收目标后停止，等待人工验收和提交。
- 不执行 GUI 自动化、启动窗口、浏览器截图或基于截图的测试。界面验收由用户手工完成。
- 引入 `c2pa`、`trustmark`/ONNX 依赖后，不再执行全量 Rust 编译；只运行前端类型检查、格式检查、静态检查和不链接重依赖的针对性测试。
- 如果静态检查不足以控制错误积累，将停止后续实现，并明确请求用户执行一次完整编译/测试。
- 不下载 TrustMark 模型；只使用 Tauri 工程 `src-tauri/resources/models/` 中随应用打包的 Q/BCH-5 encoder 与 decoder。
- 不自动创建 Git 提交。每个阶段由用户验收后自行提交。

## 数据与行为不变量

- 分组可嵌套，Artwork 只能作为叶节点；树节点使用稳定 ID，父级和同级顺序持久化到 SQLite。
- 作品树中的 Artwork 项目和包含它们的分组删除后进入回收站，可恢复或永久清理；Artwork 内部的历史节点裁剪不进入回收站。
- Artwork 至少有一个分支。分支可从任意历史节点 fork，且新分支工作文件路径必须与该 Artwork 的所有现有分支不同。
- 每个分支只有一个 head；提交创建不可变历史节点，并保存内容哈希、逻辑大小、块数量和实际 snapshot/delta 文件大小。
- 分支标题与每个历史节点标题均可修改。
- 删除历史节点会永久删除该节点及其所有后代；不提供回收站。
- 分支绑定最终成品后进入只读状态，禁止继续提交。移除成品后才可恢复提交；如果已有认证记录，移除前必须返回明确影响提示并要求显式确认。
- TrustMark 的 61 位标识是认证记录的快速关联键。识别时先按标识索引匹配所有分支，再回读 C2PA 清单并报告一致性。
- 私钥不进入持久化配置、数据库或日志。允许持久化的是证书路径、签名算法、时间戳地址和作品声明等非秘密配置。

## 阶段 1 详细验收

- `package.json`、Vite、Tauri 配置和应用入口齐全，不依赖两个源项目的运行目录。
- 应用设置使用版本化 JSON，包含窗口状态、仓库路径和内容显示偏好，并使用原子替换写入。
- 默认关闭主窗口时隐藏到托盘；托盘可以恢复窗口和显式退出，隐藏窗口不得结束后台任务。
- 新仓库只接受空目录或已有合法数据库；拒绝文件系统根目录和混入普通文件的非空目录。
- SQLite 开启外键，保存树节点、Artwork、分支、历史节点、分支 head、最终成品、认证配置和认证记录。
- schema 明确表达历史节点的单父关系与多子关系；分支工作路径在同一 Artwork 内唯一。
- 纯 Rust 测试至少覆盖：创建根分支、fork 路径冲突、成品锁禁止提交、删除祖先节点会选择完整后代集合。
- 不包含 ONNX/C2PA 依赖；允许执行一次 `cargo test`/`cargo check` 和前端构建。

## 来源映射

| 目标能力 | 来源 | 迁移原则 |
| --- | --- | --- |
| 树、拖放、多选、查询 | LilithClient `auto-backup` 前端 | 保留模块边界和稳定 ID，加入多选与搜索，不沿用线性版本假设 |
| snapshot/delta、调度、恢复 | LilithClient `backup_agent` | 保留 ChunkFile 格式与事务顺序，把 job/head 改成 Artwork/branch/history 图 |
| TrustMark 与 C2PA | Proven Rust 流水线 | 保留 Q/BCH-5、soft binding 和私钥零持久化，关联键改由分支认证记录管理 |
| 配置、窗口、文档层级 | LilithClient 应用架构 | 应用层只负责生命周期和设置，领域逻辑保持独立 Rust 模块 |

## 阶段 3 验收清单

- 非空目录先探测并读取可识别的 Lilith Artworks SQLite 数据库；只有探测和验证均失败后才报错。空标准数据库文件可初始化为新仓库。
- Tauri 主窗口禁用原生文件投放拦截，作品树拖放沿用 LilithClient 的递归 Branch/TreeRow 模式，并保留多选批量移动。
- 树分组展开状态保存到 `localStorage`；再次进入应用后恢复，已删除分组 ID 会被清理。
- 禁用按钮使用默认光标而不是等待光标；Lucide 小图标统一为偶数像素并启用 `geometricPrecision`。
- ChunkFile 从 LilithClient 原文件完整迁入，保持格式版本、分块参数、反向 delta、zstd 与完整性校验。
- 每个分支绑定独立工作文件和独立自动备份间隔；托盘驻留期间调度器持续运行，最终成品锁定分支不进入调度队列。
- 从任意历史节点 fork 前生成可共享 checkpoint；新分支仍强制使用与同 Artwork 其他分支不同的工作文件路径。
- 历史工作区支持选择分支、提交、fork、恢复和取消，显示 head/fork 标签、原文件大小、Chunk 文件大小、块数量和 SHA-256。
- 资源位于 `src-tauri/resources/`；根目录不再保留 `resources`，图标和两个 Q 模型由 Tauri 配置随包分发。
- 明确禁止 GUI 自动化、启动应用做测试和截图测试；本阶段仅运行命令行构建、静态检查和小文件恢复测试。

## 阶段 4/本轮追加验收清单

- 当前分支视图提供精简模式，选择节点后统一重建并显示进度。
- 恢复通过系统“另存为”窗口选择输出，默认建议 `<文件名主体>_restored<扩展名>` 且禁止覆盖。
- 历史总览左键仅选择节点；节点唯一属于一个分支时，右键可进入分支；分支删除需从分叉节点右键或当前分支工具区发起并二次确认。
- 全局自动备份在设置中使用开关，系统托盘根据状态动态显示暂停或继续，状态持久化。
- 本轮不执行完整 Tauri 编译、运行或 GUI 测试；仅执行前端构建、Rust 格式检查和差异检查，完整验证由人工进行。

- 全局始终显示历史节点的原文件大小、Chunk 文件大小和 SHA-256，不再提供隐藏开关。
- 自动备份提交备注为空，节点类型标记为 automatic；主动提交备注可为空，空备注节点命名为“主动提交”，不能被自动备份文案覆盖。
- 节点右键菜单提供编辑、Fork、恢复、检查点和分支操作；节点删除仅在当前分支视角提供；分支设置在主界面编辑并防抖自动保存。
- 总览以父子 mindmap 展示所有分支；HEAD/fork 标签只显示归属，不响应点击进入。
- 恢复和中间节点精简显示可取消进度；精简只允许有唯一子节点、非叶节点、非 head、非 fork 起点且非检查点的节点，并重新生成父子反向 delta。
- 删除节点及全部后代会回退当前分支并直接销毁不再引用的历史元数据和 ChunkFile；若其它完整分支占用该子树则预检拒绝并要求先删分支；作品树中的 Artwork 删除规则不变。
- 图标运行时按 LilithClient 的 ICO 多尺寸解码方法选择窗口/托盘帧，禁止依赖 WebView 缩放或 CSS 插值补救锯齿。
- 本轮只执行 `cargo fmt --check` 与 `git diff --check`；编译、Rust 测试和 GUI 测试由人工验收阶段执行。
