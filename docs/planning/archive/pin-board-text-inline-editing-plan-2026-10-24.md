## 目标

1. 文字条目可以直接在画布上的四边形里编辑，不再打开弹窗。
2. 编辑期间显示字体栏：有效字号、颜色、对齐；内容随输入实时预览。
3. 提交后文字内容、字号、颜色、对齐、测量宽高和四边形一起保存，切画板、自动保存、
   后台结算与撤销/重做都不丢。
4. 一次编辑会话只产生一条撤销记录；撤销/重做文字改动时纹理同步重建。
5. “添加文字”进入画布放置模式，左键落点出现空编辑框，提交时才创建条目。
6. 不改变仓库 schema；加粗/斜体/下划线按决策延期。

## 非目标

- 选中片段富文本（同一段文字里部分加粗/改色）。
- 加粗、斜体、下划线、字体族选择与字体列表。
- 自动换行、文本盒宽度约束、首行缩进、字距/行距等排版能力。
- 把文字四角缩放改成“直接改字号”。四角缩放仍改四边形；有效字号负责把两者合成一个
  用户可见的数字。
- 在导出、剪贴板、图层、回收站或历史分支中加入文字专用语义。
- 改造分支历史：`pin_board_history` 仍只存变换，不存文字载荷版本。

## 现有关键事实

以下为批次 1 开工前的事实，用于说明本计划要改什么；批次 1 落地后这些描述已不成立的部分
（“只有创建命令”“没有更新命令”“保存只收变换”）见 `docs/modules/pin-board.md` 的「文字就地编辑」。

- 文字目前只能通过弹窗创建，命令面只有 `create_pin_board_text`，没有更新命令；
  `docs/modules/pin-board.md` 的「命令面」也明确写着创建后不支持改字/改色/改字号。
- 文字载荷在 `pin_board_texts`：`text`、`font_family`、`font_size`、`color`、`align`、
  `measured_width`、`measured_height`。本计划只会写这些已有列，不需要迁移。
- 文字由前端按 `textLayout.ts` 度量并栅格化成 RGBA 纹理，渲染器复用既有纹理缓存与淘汰。
- `save_pin_board` 目前只接收位置、层级、删除态与 `points` / `uv`；`stateKey`、历史快照、
  `editableImages()` 和 `pendingSettle.editableItems()` 也都只处理这些字段。
- 选中框、旋转手柄与缩放柄已经是 DOM 覆盖层，位置由 `worldToScreen` 计算；就地编辑可以
  复用同一套四边形到屏幕的映射。
- 画布缩放不是 1:1：默认视口为 5000 世界单位铺满画布高度。100% 只表示默认视图比例。

## 交互设计

### 进入与退出编辑

- **第一次点击**文字：按现有逻辑选中，显示选中框与变换柄。
- **第二次点击**同一个已选中的单条文字：如果按下到抬起之间没有拖动（建议阈值 3 CSS 像素），
  进入编辑；否则仍是一次拖动。
- 进入编辑后：
  - 隐藏该文字的 GPU 纹理与选中框/变换柄，显示与四边形同位置、同旋转、同缩放的 DOM 编辑框；
  - 编辑框获得焦点，光标为 I 字型；点击进入时光标落在点击的字符边界（按行与对齐换算），
    从 `F2` 或右键菜单进入时放在文本末尾；
  - 画布上悬停在“已选中的单条文字”上时，光标显示为文本光标，提示再点一次可编辑。
- 其他入口：
  - 右键菜单在恰好选中一条文字时提供“编辑文字”；
  - 选中单条文字后按 `F2` 进入编辑。
- 提交与取消：
  - `Enter` 换行，`Ctrl+Enter` 提交；
  - 点击编辑框外部提交；
  - `Escape` 取消，恢复进入编辑前的内容与样式；
  - 中文输入法组合期间（`compositionstart` 到 `compositionend`）不提交、不响应全局快捷键。
- 内容为空时提交按取消处理；已有文字删除到空再提交时恢复原文，不删除条目。

### 编辑框

- 使用 `textarea` 而不是 `contenteditable`：纯文本、显式换行、IME 与浏览器原生文本撤销更可靠。
- `wrap="off"`，不自动换行，与当前 `textLayout.ts` 的“按 `\n` 分行、不按宽度折行”保持一致。
- 字号、字体族、颜色、行高与 `textLayout.ts` 对齐：`font-size` 用屏幕像素，`line-height`
  为 1.3，内边距为 0，背景透明，文字颜色取自条目。
- 输入时用 `measurePinBoardText` 重新测量，编辑框宽度/高度随内容增长；增长围绕原中心并保留
  原旋转方向。GPU 文字在编辑期间不重绘，只在提交后重建一次纹理。
- 文字被水平/垂直翻转（`uv` 镜像）时，第一版编辑框按未翻转方向显示，提交后仍按原 `uv`
  渲染；若人工验收认为方向切换不可接受，再改成“编辑前先归一镜像”。
- 编辑期间缩放、平移、窗口尺寸变化都要重新计算编辑框位置与屏幕字号；有效字号不变。
- 有效字号在屏幕上小于约 10 CSS 像素时，进入编辑会自动把视图放大到可读（约 20 CSS
  像素，以编辑框中心为锚点）；这是批次 2 已实现的打磨项，不改变数据库里的字号。

### 字体栏

- 浮在编辑框上方（空间不足时放到下方），保持屏幕水平，不随文字旋转。
- 控件：
  - **有效字号**：数值框 + 减/加按钮，显示“数据库字号 × 条目缩放”；
  - **颜色**：复用现有 `PinBoardColorPicker`；
  - **对齐**：左 / 中 / 右三个按钮。
- 编辑期间只改编辑草稿，不逐次写库；提交时一次性应用。改变字号或对齐时实时重新测量并调整
  编辑框，颜色只改显示。
- 字体栏上的非输入控件在 `pointerdown` 时阻止默认焦点转移，避免点颜色或对齐时先把编辑框
  当成“失焦”提交。输入法组合期间同理。

## 字号与缩放的统一口径

现状有三层尺寸：

1. `fontSize`：数据库里的世界单位字号；
2. 条目缩放：四边形宽 ÷ 文字测量宽，由四角拖动或工具栏缩放改变；
3. 画布缩放：只改变视口，屏幕像素与世界单位的比例随之变化。

屏幕字号与有效字号的关系：

```text
有效字号（世界单位） = fontSize × 条目缩放
屏幕字号（CSS 像素） = 有效字号 × 画布高度 ÷ 视口世界高度
```

处理规则：

- 字体栏永远显示**有效字号**，不显示屏幕像素；画布缩放不写回字号。
- 编辑框的屏幕字号按上面的公式计算，因此任何画布缩放下都与画面上的字对齐。
- 用户修改有效字号时，按当前条目缩放反算 `fontSize = 有效字号 ÷ 条目缩放`，重新测量宽高，
  围绕原中心和原旋转方向重建四边形；条目缩放保持不变。
- 这样数据内部仍保留“字号 + 条目缩放”两层，但用户只面对一个数字；不采用“进入编辑时把缩放
  烘焙进字号”的方案，避免撞字号 1000、测量宽高 8192 的现有上限。
- 有效字号输入范围沿用现有 UI 口径（12–240）即可覆盖常见情况；若反算出的 `fontSize` 超出
  `(0, 1000]`，提交时给明确错误并保留编辑状态，不静默夹值。
- 未来若要让“文字四角缩放”直接改字号，应另立计划；本计划不改变现有缩放行为。

## 保存契约

### 前端 DTO

`PinBoardEditableItem` 增加一个可选的文字载荷，仅文字条目使用：

```ts
interface PinBoardEditableText {
  text: string;
  fontSize: number;
  color: string;
  align: PinBoardTextAlign;
  measuredWidth: number;
  measuredHeight: number;
}
```

- 普通保存只对**文字签名发生变化**的条目携带该字段；未变化的文字不带内容，避免每次拖动都
  传输整段文字。
- 渲染器维护每条的“已保存文字签名”；编辑提交、撤销、重做时更新，保存成功后把签名推进到
  请求时的值。保存期间又发生编辑的条目不能被误记为已保存。
- 后台结算快照已经保存完整 `PinBoardItem`，写回时对文字条目一并携带载荷；切换画板不丢编辑。
- 文字宽度/高度仍取 `measured_width` / `measured_height`；前端在提交时用同一套
  `measurePinBoardText` 重新计算。

### 后端

- `EditablePinBoardItem` 增加 `text: Option<EditableTextPayload>`；字段可选，旧调用方不传时
  行为不变。
- 保存时：
  - 文字条目带载荷：校验内容、字号、颜色、对齐、测量宽高；在**同一事务**里更新
    `pin_board_texts`；
  - 非文字条目带载荷：拒绝；
  - 文字变化参与 `changed` 判定，从而推进 step、作废未来步骤并 bump revision；
  - 文字变化与变换变化合并为一次保存，不产生两次 revision。
- `pin_board_history` 仍只存变换；文字载荷只有当前版本。一次文字编辑提交会写一个 step
  （即使只有颜色变化、变换未变），用来保持“保存推进 step、作废 redo”的既有语义；该 step
  不记录文字历史，撤销/重做由前端内存历史完成。
- `create_pin_board_text` 保持不变，新建仍走创建命令；`pin_board_texts` 的校验逻辑抽成
  共享函数，创建与保存更新共用。
- 不需要新增 Tauri 命令，也不需要改 `command_registry.rs`。

## 撤销与重做

- 进入编辑时不对模型做任何修改；编辑框持有草稿。
- 提交时取进入编辑前的快照与提交后的快照，调用一次 `pushHistory`；中间每字、每次字号/颜色/
  对齐变化都不进历史。
- `ImageSnapshot` 扩展文字载荷与测量宽高；`snapshot()` / `restore()` / `stateKey()` 同步覆盖。
- 撤销/重做恢复文字载荷后：
  - 销毁该条目的高清与预览纹理；
  - 清掉 `textureQualityCaps` 与 `failedTextureDimensions` 中该条目的记录；
  - 重新排队纹理加载；
  - 选中框、包围盒与图层计数按新四边形/内容更新。
- 新建文字仍按现有 `applyMutationResult` 产生一条创建撤销记录。
- 编辑期间按 `Ctrl+Z` 由 `textarea` 自己撤销输入，不触发画板撤销；提交后画板撤销一次回退
  整个编辑会话。

## 编辑会话的边界

- **切画板 / 切作品**：先把草稿同步提交进渲染器模型，再走现有 `detachCurrentBoard` /
  `stageBoardSettle`；这样文字载荷随快照进入后台结算，不依赖一条还在飞的独立命令。
  **新建草稿**还没有模型，切画板、锁定与退出时直接丢弃；全屏只改布局，编辑框保留。
- **自动保存**：编辑期间模型没有变化，自动保存不会写半成品；提交后才重新排程。代价是进程
  被强杀会丢掉未提交的编辑草稿，这是为“一次会话一条撤销”接受的取舍。
- **锁定 / 全屏 / 退出**：先提交，再锁定、调整布局或结算。
- **导出**：编辑期间禁用整画布导出与位图导出入口；点击外部提交后恢复。导出始终读已提交的
  纹理与模型，不读编辑草稿。
- **复制 / 粘贴 / 删除 / 图层切换**：编辑期间禁用这些模型操作；点击外部提交后再执行。
- **图层被隐藏**：若编辑中的文字所在图层被隐藏，先提交再隐藏，避免看不见但仍在编辑。
- **画板被其他窗口修改**：沿用现有 revision 冲突处理；提交失败时保留草稿并显示错误，不丢弃
  用户输入。

## 渲染与纹理

- 编辑期间在 `draw()` 中跳过该条目，避免 DOM 编辑框和 GPU 文字重影；选中框与变换柄一并隐藏。
- 提交、撤销、重做后调用统一的 `invalidateTextTexture(itemId)`：
  销毁 `textures` / `previewTextures` 中的旧纹理，清质量上限与失败记录，`scheduleLoads(0)`。
- 文字纹理请求继续走 `requestedTextTextureDimension`，使用更新后的 `width` / `height` 与显示
  长边；不需要新的纹理格式或缓存。
- 整画布导出继续使用已提交纹理；导出期间不允许编辑，避免导出到一半文字改变。

## 新建文字的流程

- 两条入口，都不再打开对话框：
  - 主工具栏“添加文字”进入**文字放置模式**：画布光标变为 I 字型、按钮点亮，左键在落点
    打开空白编辑框；右键、`Escape` 或再次点击按钮取消。放置模式不显示底部提示条——光标与
    按钮态已经说明当前状态。
  - 画布空白处右键“添加文字”自带落点，**直接在右键位置打开空白编辑框**，不经过放置模式。
- 落点是文字中心，字体栏同步出现。
- 默认字号、颜色与对齐沿用上一次提交的值；首次使用为 48 / `#000000` / 居中。
- 提交时：
  - 内容为空则取消；
  - 用 `measurePinBoardText` 测量，调用现有 `create_pin_board_text`（角度固定 0，条目缩放为 1）；
  - 成功后关闭编辑框、选中新条目并记住本次样式，不写状态栏；失败时保留编辑框与输入内容，
    原因同时写状态栏与编辑框。创建命令是瞬时的，不显示传输进度条。
- 新建文字不经过 `save_pin_board` 的文字载荷扩展，仍由创建命令一次落库；之后再次编辑才走
  保存链路。

## 限制与校验

- 内容 1–5000 字符；测量宽高 ≤ 8192；数据库字号 `> 0` 且 `≤ 1000`。
- 颜色按现有规则归一化；对齐只接受 `left` / `center` / `right`。
- 有效字号输入 12–240；反算后的数据库字号越界时提交失败并提示，不静默截断。
- 单行文字过长、测量宽度超过 8192 时提交失败；编辑框保留，提示缩短内容或减小字号。
- 文字条目被翻转时按本计划的镜像口径处理；不新增“翻转后不可编辑”的硬限制。

- 编辑期间缩放、平移、窗口尺寸变化后编辑框仍贴合文字；旋转文字可编辑。
- 字号/颜色/对齐实时预览，提交后纹理清晰且位置不跳。
- 一次编辑会话只产生一条撤销；撤销/重做后内容与纹理都正确。
- 切换画板、自动保存、锁定、全屏、退出、导出期间不丢编辑或写出半成品。
- 新建文字不再弹窗，空内容取消，超限提示明确。
- 收尾改动（去掉放置模式底部提示与新建成功状态、右键菜单直接落点）另行复验。

## 风险与取舍

1. **HTML 编辑框与 canvas 栅格化不可能像素完全一致**。编辑时以 DOM 编辑框为准，提交后
   重绘可能轻微落位。统一字体族、行高与内边距后接受这个差异，由人工验收手感。
2. **点击编辑与拖动的冲突**。第二次点击可能在选中文字上开始拖动；用 3 CSS 像素阈值区分，
   超过阈值仍按拖动处理。
3. **保存契约从“纯变换”变成“可带文字”**。所有保存调用方都要理解可选字段；后端必须拒绝
   非文字条目携带载荷，前端必须只发送改动文字，避免保存体积无谓增长。
4. **文字-only 保存会写一个变换未变的 step**。这是为了保持 save 推进 step、作废 redo 的
   语义；`pin_board_history` 仍不承载文字版本，跨会话的文字撤销不存在（与现有画板撤销一致）。
5. **编辑期间不自动保存**。强杀会丢草稿；提交后立即进入现有脏标记与自动保存流程。
6. **旋转/镜像文字**。旋转可正常编辑；镜像第一版按未翻转方向显示，提交后恢复原镜像，
   需要人工确认观感。
7. **超长文本**。不自动换行，单行过长会撞 8192 测量上限；提示必须明确。
8. **不引入 B/I/U**。样式延期到下一次 schema 升级，避免本计划同时承担迁移风险。
