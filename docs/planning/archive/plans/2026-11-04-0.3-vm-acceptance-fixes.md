## 3. 批 1：历史与备份的清理/失败语义

### 3.1 作品 `temp` 自动清扫

**目标**：异常中断留下的 `.tmp*` 不再长期占空间；垃圾扫描继续作为非 `.tmp*` 孤儿和用户确认删除的
兜底。

**实现**：

- 在 `src-tauri/src/cleanup.rs` 增加作品临时目录清扫：遍历 `artworks/*/temp/` 顶层，只删除
  修改时间早于 `SCAN_GRACE_MS`（30 分钟）的 `.tmp*` 普通文件；不递归、不跟随符号链接、不动目录和
  其它命名。名字判定复用 `cleanup::is_scratch_file_name`，与根 `temp/` 清扫保持同一规则。
- 注意 `.tmp*` 前缀规则当前有两份实现：`cleanup::is_scratch_file_name` 与
  `history::contracts::is_scratch_name`（后者的注释解释了 `NamedTempFile` 的命名来源）。新增清扫只
  用前者，不改后者的语义；若两处继续各写一份，改动其中一条规则时会漏掉另一处，需在实现时于任一处
  注明「另一份在 …」，或在收尾时合并为一个 `pub(crate)` 判定。
- 复用根 `temp/` 清扫的日志与容错口径：失败只计数并写日志，不阻断仓库打开；没有 `temp/` 目录按
  空处理。
- 在 `AppState::ready_repository_path` 首次成功校验一个仓库路径后调用一次（切换仓库后再次触发），
  调用前释放 `validated_repository` 锁；保留设置保存路径现有的根 `temp/` 清扫。
- `cleanup::scan_unreferenced` 不改：它仍会报告作品 `temp/.tmp*` 与其它孤儿，宽限期后由用户确认
  删除。自动清扫只处理确定安全的 `.tmp*`。

**测试**：

- 单元测试：过期 `.tmp*` 删除；宽限期内、非 `.tmp*`、目录、符号链接保留；多个作品目录；缺失
  `temp/` 不报错；删除失败只计数。沿用 `sweep_repository_temp_at(root, now_ms)` 的写法，时间由参数
  注入，测试不依赖系统时钟。
- 回归：强杀/断电近似后重开仓库，`artworks/*/temp` 的过期 `.tmp*` 消失；垃圾扫描仍能报告其它
  孤儿；根 `temp/` 的预览会话目录不被误删。

**风险与回滚**：删除不可逆，但只碰宽限期外的 `.tmp*` 普通文件；启动/切换时执行，避开进行中的
操作。出问题可单独回退本批，不影响 schema 与历史数据。

### 3.2 手动提交失败改为提交区内联提示

**目标**：手动提交失败不再伪装成自动备份失败，也不再承诺「按策略重试」。

**实现**：

- 后端：`src-tauri/src/app/usecases/backup.rs` 的 `commit` 不再调用
  `history::record_branch_failure(BranchFailure::Manual)`；自动备份失败路径保持不变。
- `history::schedule_repository::BranchFailure::Manual` 若没有其它调用者则删除该变体及对应测试；
  `Automatic` 与 `Ineligible` 不动。
- 前端：`useHistoryController` 增加 `commitError` 状态，提交失败时写入、成功/切换分支/卸载时清空；
  `HistoryModule` 在提交按钮附近渲染该错误，不再把提交失败送进全局错误提示。
- 提交完成但刷新历史失败仍走原有提示，不并入提交失败。

**测试**：

- 前端 controller/component 测试：失败显示在提交区、成功后清空、切换分支清空、不再出现
  「备份失败，将按策略重试」。
- Rust 测试：手动提交失败不写 `branches.last_error`；自动失败仍递增失败次数与重试时间。
- 人工：只读仓库或写满磁盘触发一次提交失败，确认提交区显示原文、分支状态不变。

**风险与回滚**：手动错误不再跨页面/重启保留，这是维护者明确接受的取舍；不改 schema。

## 4. 批 2：设置与界面状态

### 4.1 仓库路径保存前确认新建

**目标**：路径打错时不再静默建空库；新建仓库仍然方便。

**实现**：

- 新增只读命令 `inspect_repository_path(path)`，返回 `missing`、`not_directory`、
  `empty_directory`、`repository` 或 `non_repository_directory`；`repository` 包含可迁移的旧文件名
  数据库，探测本身不创建目录、不初始化数据库。命令在 `app/command_registry.rs` 登记，前端只在
  `src/app/api.ts` 增加对应包装，不直接 `invoke`。
- `useSettingsController.save` 在仓库路径变化时先探测：
  - `missing` 或 `empty_directory`：弹共享 `ConfirmDialog`，说明将新建仓库；确认后带
    `allow_create` 保存，取消则保持弹窗；
  - `repository`：照常保存（旧库迁移沿用现有发现与改名流程）；
  - `not_directory` 或 `non_repository_directory`：直接报错，不写设置。
- `save_app_settings` 增加 `allow_create` 参数；未确认时遇到缺失目录返回可读错误，防止绕过界面
  静默建库。`prepare_repository` 的初始化路径只在 `allow_create` 为真时执行。
- 保持现有行为：路径未变化时只验证现有数据库，缺失时拒绝静默重建。

**测试**：

- Rust：探测五种路径状态；未允许新建时缺失目录被拒绝且不落盘；空目录确认后初始化；非空非仓库
  目录被拒绝。
- 前端：确认弹窗出现、取消不保存、确认后保存；五种状态的错误文案。
- 人工：输入不存在路径、空目录、含无关文件的目录、有效仓库各一次。

### 4.2 素材板不可用时禁用新建

- `PinBoardSidebar` 接收 `unavailable`，禁用标题栏新建按钮和列表右键菜单的「新建画板」。
- `PinBoardModule` 把现有 `unavailable` 传给侧栏，并交给 `usePinBoardController`（新建入口实际在
  该 hook 的 `createBoard`），在入口按 `unavailable` 拒绝，防止键盘或其它入口绕过按钮；空状态提示
  不再引导用户点击不可用的入口。
- 测试：不可用时按钮与菜单项禁用、直接调用创建也被拒绝；可用时行为不变。

### 4.3 删除发布记录后清空成功横幅

- `usePublicationController.deleteRecord` 在删除成功后，如果 `result` 对应的就是被删记录，清空
  `result`、`publishMetrics` 与待发布水印 ID；删除其它记录不清当前横幅。
- 测试：删除当前记录后横幅消失；删除其它记录横幅保留。

### 4.4 TrustMark 识别提示与模块文档

- `IdentificationView` 空状态改为：C2PA 始终读取；TrustMark 对框选区域更可靠，整图可能检不出
  小区域水印。
- `docs/modules/authenticity.md` 的识别段落补同一限制；不承诺整图必检出。
- 测试：更新断言文案；不新增解码逻辑。

### 4.5 最小窗口宽度验收基线

- 不改 `minWidth` 与布局。验收基线改为「最小窗口宽度约 945 像素（125% 缩放下实测），945 下无
  截断」。
- 口径说明：`minWidth` 是逻辑像素 760，125% 缩放下约合 950 物理像素；实测 945 与之只差约 5 像素，
  视为同一设计下限，差别在测量误差范围内。历史计划里的 900 是早期布局断点，不是窗口下限，不再作为
  验收基线。若后续复验发现实测值与 950 稳定相差更多，应按实测值重新记录单位与数值。

### 4.6 区域叠加层复现步骤（不修）

在修复批 2 后按以下步骤复验一次；只有稳定复现才重新开项：

1. 打开有认证记录的分支，在发布页框选「区域 1」；
2. 不点发布，切到「识别与溯源」；
3. 拖入一张图片，确认预览区是否出现任何「区域 1」标签或旧框；
4. 再切回发布页、切换作品、切换仓库，各看一次。

若识别页只显示「识别框选区域」且无旧框，维持「未复现」结论。

### 9.3 收尾审查修正

- 取 owner lock 会往目标根目录写锁库，而原实现里「空目录或非仓库目录 + 未确认新建」的保存在
  报错前已经在这个目录落下一个 `.lilith-write-lock.sqlite3`。现在 `check_repository_target`
  在任何取锁之前做同一遍只读探测，`prepare_repository` 在切换闭包内复检，防止探测与取锁之间
  目录被外部改动；错误文案只保留一份。
- 回归测试 `rejected_repository_saves_leave_the_target_directory_untouched` 对空目录与非仓库
  目录各做一次未确认保存并核对目录项数量。去掉预检时该测试在空目录上失败（多出锁库文件）。
