## 11. 素材板「画板内复制、橡皮擦与导出收敛」阶段 1（2026-10-21，通过）

`pin-board-copy-eraser-export-plan-2026-10-21.md` 阶段 1 的四项交互（橡皮擦、图层计数、「大小」
文案、导出收敛、画板内复制/粘贴扩到三类条目）连同两项阶段外补充落地后，维护者在真实画板上
完成验收，**全部通过**。验收项已从 `../todo.md` 删除，`../current-handoff.md` 只留「阶段 2
未开工」这一条指针；实现口径见 `../../modules/pin-board.md` 的「绘制」「橡皮擦」「点选与框选的
命中」「图层可见性」「命令面」，行为变化见 `CHANGELOG.md` 的 `## Unreleased`。

**验收结论**（逐项通过）：

- 橡皮擦：`E` 后出现环形光标，直径随「大小」与缩放变化；单击即擦掉、拖拽增量擦，一次拖拽
  一条撤销记录，空点松手不留历史也不标脏；快速来回擦动擦得掉（擦除按两帧之间扫过的轨迹判）；
  隐藏标注层时按下无反应，锁定后工具退回选择、光环消失，`pointerleave` 与切工具后不残留。
- 画板内复制/粘贴：位图 + 文字 + 笔迹混选粘贴后整组相对位置不变、外框中心落在放置点，图层
  沿用源条目、笔迹仍在标注层；源画板移入回收站后粘贴被拒且不留半份副本。位图粘贴的落位与
  旧行为不同（不再按导入阵列重排），维护者已确认接受。
- 导出与右键置灰：只选文字或笔迹时「导出图片」「复制图片到剪贴板」按钮与右键两项一起置灰、
  点击与快捷键均无反应且不弹提示；混选时只写位图文件，计数与实际文件数一致。
- 图层面板：四行数字正确，隐藏某层后数字不变，标注层不显示数字，行高不变，屏幕阅读器读到的
  行名仍是层名而不是「顶层 12」。
- 点选与框选按墨迹判：点矩形/椭圆内部不选中、点描边选中；框住空心内部不选中；1–3 px 细线偏
  一个像素仍点得中；框选大片区域时拖拽不掉帧。该口径与 Figma/PS 的包围盒不同，属已确认的
  行为变更。

**与计划文本的偏差**（均已在代码与模块文档里定稿）：

- 图层面板只给数字加 `aria-hidden` 不够，行按钮另补 `aria-label={row.label}`，可访问名不再依赖
  文本拼接。
- 右键菜单原本没有禁用条件，给 `PinBoardContextMenuRequest` 补 `exportableCount`，两项据此置灰。
- `begin_item_mutation` 改按 kind 数组接参（混合粘贴里每条 kind 不同，只有位图需要预建
  `pin_board_bitmaps` 占位行），粘贴、导入、文字、笔迹四条写入路径都改传数组。
- 导出 id 同步收窄：新增 `renderer.exportableImageIds()`，混选时不再把文字 id 交给只认位图的
  原生命令。
- 环形光标挂在画布外层（`canvas.parentElement`）而不是 `.pin-board-stage`，层级低于图层面板与
  标注工具条；擦除命中额外覆盖箭头头部三角（只按杆判时从侧面擦箭头擦不掉）。

**阶段外补充**（维护者在验收过程中提出，同批落地）：

- 笔迹的碰撞箱改为绘图区域：点选与框选都按墨迹判，与橡皮擦共用 `strokeHit.ts` 的世界折线，
  另加 3 CSS 像素最小容差保证细线可点；位图与文字保持四角框。
- 橡皮改为按扫过的轨迹判（`strokeHitBySweep`）：只判采样点时，`pointermove` 被合并到 60–120 Hz，
  快速擦动会跳过细笔迹，表现为「反复擦没反应、点一下反而擦掉」。

**自动验证**：`npm run test:pin-board` 22 文件 / 230 用例、`npx vitest run` 45 文件 / 407 用例、
`npx tsc --noEmit`、`npm run build`、`cargo test pin_board --lib` 73 用例（含三条新增粘贴用例）、
`cargo check --tests` 全部通过。

## 12. 素材板整画布导出（计划阶段 2，2026-10-21 通过并归档）

**实现**：离屏 `rgba8unorm` 渲染通道（与屏幕共用着色器与绑定布局，只有目标格式不同的管线
副本，`createBoardPipelines` 一份代码建两套）、按导出倍率重载纹理（单张要吃四分之一预算就不
升级、当前块涉及的条目在淘汰时受保护）、行带分块与回读、原生流式拼装 PNG（`canvas_export.rs`
建临时文件 → 逐块收原始 RGBA → 写 IEND → `sync_all` → 原子改名，不取仓库写租约与操作锁）、
导出对话框与进度/取消/画板锁定。同批落地图片导入/导出的取消（`cancel_pin_board_transfer` 与
`pin_board::transfer::PinBoardTransferCancel`）与三条链路共用的进度条。口径见
`docs/modules/pin-board.md` 的「整画布导出」，行为变化见 `CHANGELOG.md` 的 `## Unreleased`。

**验收结论**（维护者 2026-10-21 实测，逐项通过）：小画板 1x 导出的背景透明、内容位置与笔迹
观感均与屏幕一致；倍率与像素宽度互相对齐（含手动填 1 时的「超过建议上限」警告、清空再失焦
复原）；文件名带中文/空格/非法字符与边距 0–64 都按预期落盘，重名追加 `-2`；导出中途取消
（含全屏）不留 `lilith-pin-board-export-*` 临时文件、画板随即解锁；导入图片取消后不留半批
条目、导出图片取消后已写出的 PNG 完整可用；导出中切画板/切作品自动取消且不报 revision 冲突；
导出与后台完整性扫描/自动备份并行完成、不报 `repository_busy`；无 WebGPU 环境入口禁用；
导出期间工具栏、图层面板、画板列表与标注工具条一并置灰；空白处右键入口能打开对话框。

**验收后的命名修订**：入口文案由「导出整画布」定为**「导出画布」**（对话框标题、工具栏提示与
右键项统一，设置页说明改写为「导出画布时的最长边」，原生侧两条错误文案改为「当前没有进行中
的画布导出」）。代码注释与文档章节仍用「整画布导出」描述机制本身——它说的是「整块画板合成
一张透明 PNG」这件事，不是入口名。

**与计划文本的偏差**：见归档计划 `pin-board-copy-eraser-export-plan-2026-10-21.md` 的「阶段 2
实施记录」与「阶段 2 交互修订」两节（`begin` 多一个 `file_name`、行带实际行数 1048/419/279、
超限不弹二次确认而改主按钮、纹理降级落在单张粒度、导出外框排除 `available = false`、块宽

**收尾复核**：新增 `renderer.isDrawable()` 收口「未删除 + 可用 + 所在图层可见」这条在屏幕绘制、
