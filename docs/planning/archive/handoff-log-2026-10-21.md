# 2026-10-21 归档：alpha5 人工验收收口与 0.3.0-alpha.5 切分

- 归档日期：2026-10-21
- 范围：素材板笔迹、形状与图层（alpha5）阶段 2–5 的全部人工验收结论、线宽滑条新映射的手感复测、
  同日两个搭车批次（备份检查元数据接线、手动重查分支按链校验）与快速命中计数批次的记录，以及
  alpha5 收口与 `0.3.0-alpha.5` 的版本切分。
- 状态：alpha5 阶段 1–5 已全部实现并通过人工验收，切分为 `0.3.0-alpha.5`（未打标签）。
  **0.3 尚未完成**：alpha4 时代批次的若干 GUI 验收项、待查集合的优先级确认与发布前压力测试
  （含 `manual` 档）见 `../todo.md`。

## 1. 素材板渲染观感（笔迹阶段 2，通过）

维护者在具备 WebGPU 适配器的机器上打开含笔迹的画板，逐档缩放 10%–800% 确认：五种工具
（自由笔、直线、箭头、矩形、椭圆）的边缘干净、细笔不断裂；选中笔迹时包围框描边与图片一致；
画板里只有笔迹时不出现「正在加载」或红色失败占位框。**通过并归档**，相应条目已从
`../todo.md` 删除。实现口径见 `../../modules/pin-board.md` 的「渲染」。

## 2. 绘制交互与浮动工具条（笔迹阶段 3 修订后，通过）

维护者实测确认：连续快速画多笔不再报「画板已被其他窗口修改」、每一笔都落库、重开画板笔迹
仍在；绘制工具下画完不出现包围框，切回选择工具后仍能拖动/旋转/缩放笔迹；浮动工具条在画布
下方居中，`T` 收起/展开（全屏下仍可用），收起后仍可用快捷键换工具；线宽文字单行、滑条与
数值框同步；取色浮层正常弹出且在窄窗口内不越界；预览与落库后的位置、粗细、颜色一致，松手
不闪空白；Shift 四种约束（直线、正方形、圆、45° 吸附）正确；拖拽不足 3 像素不产生条目。
**通过并归档**。粗箭头三角略微超出选中框此前已由维护者确认可接受（2026-10-21），本批次未改。

## 3. 图层可见性（笔迹阶段 4 改版后，通过）

面板改为画布左上角的浮动可收起面板后复测：窄窗口与全屏下位置正确、收起/展开顺手、四个开关
观感正常、面板不遮画布内容；被隐藏的内容点不到、框选框不到、`Ctrl+A` 选不到、不会被导出；
隐藏标注层后「重置视图」不会缩放到空白；先选中某层的条目再隐藏该层，选中被取消；选中笔迹时
右键菜单的图层三项置灰并给出说明；切走画板再切回，四个开关保持（重启后回到全部显示，预期）。

两项已定行为经维护者确认**接受**：混选（图片 + 笔迹）时整组拒绝改图层（而不是只改图片）；
新条目落进隐藏层时自动打开该层。**整项通过并归档**。实现口径见 `../../modules/pin-board.md`
的「图层可见性」。

## 4. 线宽滑条新映射与几何修复批次（通过）

2026-10-21 的素材板线宽、光标与笔迹几何修复批次（线宽上限 64 → 500、滑条指数映射 + `t^0.75`
压平、笔尖光标、图元按「半个线宽 + 羽化余量」外扩、椭圆距离场改隐函数值 / 梯度长度、自由笔
改斜接带）中，几何观感与笔尖光标已由维护者实测确认；本次复测补上最后的滑条手感：细线端
（1–20）能一档一档调，右半段不再一拖就窜到 500，200–500 这段拉得开，数值框与滑条始终同步，
手输 500 滑条停最右端、手输 1 停最左端。**整批通过并归档**，行为变化见
`../../../CHANGELOG.md` 的 `## 0.3.0-alpha.5 - 2026-10-21`。

## 5. 采样与压感手感（笔迹阶段 5，通过）

维护者用真实数位笔确认：落库前后的位置、粗细、颜色一致，两端 taper 自然、尖角不被抹圆、
快速划线不断裂，松手不出现「突然变粗/变细」；无压感设备的轻描不会反而最粗。**通过并归档**。

**已确认的验收限制**：维护者的数位笔驱动无法开启「鼠标模式」，`pressure` 恒 0.5 时回退成
整笔等宽一项未能实测。实现上该回退与压感判定共用同一条件（指针是笔且确实收到过非零压感），
维护者接受该限制，不再另行安排。

## 6. 性能指标（笔迹阶段 5，按维护者口径关闭）

计划的逐档帧率人工测量（500 笔 60 fps、2000 笔 ≥ 45 fps、5000 笔 ≥ 20 fps）在真实使用中
不可行——维护者画不到合成规模的笔数；实测为实际绘制大量笔迹观察，**暂无卡顿**，据此确认
可接受。打开画板耗时与 Rust 侧批量读写已由 P9 发布档自动压测覆盖（数值在
`tests/perf-baseline.json` 与 `../../user/stress-test-report.md` 的「2026-10-21 复跑摘要」）；
开发构建的 `__lilithPinBoardStrokeProbe()` 保留，后续需要量化 CPU 侧采样/编码/缓冲成本时可用。
该项按上述口径关闭并归档，不再逐档人工复测。

## 7. 备份检查元数据接线（GUI 验收通过）

本批次把 v5 → v6 迁移时搭车建在 `branches` 上的 `last_check_elapsed_ms` 与 `last_check_mode`
接进调度器与历史页：每次成功自动检查后写库（快速命中 `quick` / 退回全量 `fallback` / 直接
全量 `full`），`due_at_ms` 优先用本进程刚记下的耗时、重启后回退到库值，分支状态行在「最近
成功」后显示「上次自动检查：快速检查命中（12 ms）」这类说明；手动提交不写这两列。维护者实测
确认：三种检查方式与耗时的显示都正确；重启应用后「上次自动检查」仍在（读的是持久化列）；
手动提交只刷新「最近成功」时间、不改写方式与耗时。**通过并归档**。模块口径见
`../../modules/history-and-backup.md` 的「调度」与「手动入口」。

## 8. 手动重查分支按链校验（耗时确认通过）

本批次把 `reverify_branch_history` 从逐节点各自回溯改为复用全库扫描的按链遍历内核：分支内
每个 head、检查点与分支起点作为独立起点，共享前缀只解析一次；节点级结果与失败归因不变。
维护者在一条较长、带多个检查点的分支上实测「重新检查此分支」：节点状态结果与改动前一致
（正常/丢失/损坏/无法检查的归类不变），操作耗时随链长近似线性增长，长链不再明显变慢。
**通过并归档**。模块口径见 `../../modules/history-and-backup.md` 的「全库扫描按链走」。

## 9. 快速命中计数与自适应强制全量（记录收档）

v6 搭车三列的最后一项 `branches.quick_hit_count` 已接线：快速命中后计数 +1，任何全量、退回
全量与成功的手动提交清零；调度器在每次轮到分支时现算阈值
`N = max(1, min(8 × 队列档 × 尺寸档, 7 天 / 有效检查间隔))`，达到阈值的那次检查跳过指纹、
直接按全量路径完整读一次工作文件。本批次只改调度侧、不改界面，无人工验收项；数值与依据见
`../../modules/history-and-backup.md` 的「调度」。此节仅把已完成的批次记录从表层文档收进
归档，无新增结论。
