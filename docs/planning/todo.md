## 0.3 预研计划

`0.3-architecture-algorithm-plan-2026-10-05.md` 是面向 0.3 的架构与核心算法改进提案，尚未
实施，不改变 0.2 的验收口径；实施时按阶段重新登记具体未完成项。

该提案分两批交付：**0.3-alpha1 架构与算法底座**（§3.A–E，阶段 1–5，不改 schema）；**0.3-alpha2
功能批次**（§3.G/H/F + §3.I，阶段 6–9，共用一次 v4 → v5 迁移）。划分依据与依赖顺序见其 §0.4。
其中 §3.I「空闲链路校验重构」为 2026-10-17 按维护者口径新增：默认关闭、按空闲时机触发、以
「恢复链根文件 + 逐块验哈希」证明全链健康，所需 `branch_notices` 告警表随阶段 7 的
v4 → v5 迁移建立。

其中 §3.D（分块、恢复与完整性算法）已有来自本地研究仓 `research/compression-optimization/`
的实测回流提案（v2 采用集 = 格式 v2 + O2 容器感知分块 + 快照去重 + O5 鲁棒性；O6 解码域转码
已否决），实施时以该提案为规格。

## 二、维护者决策记录

2026-10-17 维护者就下列事项给出结论：

- **标签与版本推进**：2026-10-17 切版本到 `0.2.0-rc.4`；本阶段仍**不打任何标签**，版本切分与
  打标签（含 `0.2.0`）一并后议。`v0.2.0-rc.2` 仍是最近一个已打标签的候选版。自动门槛与人工
  门槛的当前状态见 `current-handoff.md` 的「当前批次状态」。
- **空闲链路校验重构**：已落地口径存在的问题维持 0.3 计划
  `0.3-architecture-algorithm-plan-2026-10-05.md` §3.I 的重构安排（默认关闭、按空闲时机触发、
  全链恢复校对、`branch_notices` 共享告警），归 0.3-alpha2 阶段 9，0.2 不再调整其口径。
- **签名**：Authenticode 签名仍无法进行。按 `docs/guides/release-policy.md`，未配置证书输入时
  允许未签名发布，但发布说明必须显著披露未签名状态及 SmartScreen 影响；签名相关的人工门槛项
  在签名可用前无法执行。
- **私密漏洞报告**：GitHub 私密漏洞报告渠道已开启，满足发行政策「正式版前必须启用并实测」的
  前置项；公开 issue 仍只用于请求建立私密联系。
