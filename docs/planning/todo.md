### 0.3 收尾人工复验（修复批次）

修复批次的实施记录见 `archive/plans/2026-11-04-0.3-vm-acceptance-fixes.md` 第 9 节。以下各项
需要在 `0.3.0-beta.2` / `0.3.0` 候选构建上人工确认，`0.3.0-beta.1` 的通过结论不能沿用：

- 历史：强杀或断电近似后重开仓库，`artworks/*/temp` 中超过 30 分钟的 `.tmp*` 消失，垃圾扫描仍能
  报告其它孤儿。
- 手动提交：只读仓库或写满磁盘时提交一次，失败提示落在提交区，分支状态不再显示「备份失败，将按
  策略重试」。
- 设置 → 仓储：不存在的路径与空目录各弹一次「新建作品仓库」确认，取消不保存、确认后建库可用；
  含无关文件的目录只报错且内容不变；有效仓库与旧文件名库直接保存并照常迁移。
- 素材板（无 WebGPU 的环境）：侧栏与列表右键菜单的「新建画板」禁用，空状态提示改为不可用说明。
- 发布：删除成功横幅对应的记录后横幅、指标与水印 ID 一并消失；删除其它记录时横幅保留。
- 识别页：确认空状态的新限制说明；按修复计划 §4.6 的步骤复查区域叠加层，只有稳定复现才重新开项。

### 架构审查整改 B2 右键菜单

作品树（含「新建」菜单）与历史节点菜单已统一到共享 `ContextMenu`；以下四项需在 Tauri

### 架构审查整改 B5 素材板

`renderer.ts` 已拆出快照、撤销栈、笔迹图层与纹理淘汰策略，前端与 Rust 自动化测试通过；
虚拟机验收只覆盖了无 WebGPU 的降级路径，以下画板流程仍需在支持 WebGPU 的真机复验（实施记录见
`archive/plans/2026-11-03-architecture-review-remediation.md` 的 B5 实施记录）：

- 切换画板与切换作品：有未保存改动时走后台结算，切回内容仍在；无改动时不产生写操作。
- 撤销/重做：拖拽、缩放、旋转、翻转、图层切换、文字提交与擦除各产生预期的一条记录。
- 文字编辑：就地编辑、放置模式、新建与已有文字的提交/取消、字号与颜色更新。
- 擦除：一次拖拽一条撤销记录，扫过路径能擦掉两次采样之间的细笔迹。
- 整画布导出：普通倍率与超建议上限、取消、导出期间交互锁定与结束后的自动保存恢复。
- 退出结算与 GPU 设备丢失恢复：关闭工作区/切仓库/退出时保存当前画板，设备丢失后按限流
  重建并恢复纹理与笔迹。

### 切换作品的画板交接

- 素材板里有未保存改动时切换作品：不弹错误，页头下方短暂出现「正在后台保存 1 块画板的改动」
  后消失；切回去内容仍在。扫同一作品的两块画板之间来回切也走同一条路径。该提示存在时间很短，
  需要录屏或更慢的保存路径才能捕捉。
- 把仓库目录改成只读（或写满磁盘）后做一次画板编辑再切换：出现常驻的「N 块画板的改动还没写进
  仓库：…」+「重试」，画布与作品一致；恢复可写后点「重试」即写回、提示消失。要验证该分支，需要
  一种「数据库仍可打开、但保存时写入失败」的条件（例如真实磁盘写满）；整仓 ACL、只锁数据库与
  只锁画板目录分别会在更早的仓库校验、SQLite 打开或数据库布局写入阶段走别的分支。

  并发数量管住（毫秒级微任务直通，不排队、不参与调度决策；主窗口只看一个作品，渲染引擎
  仍只有一份，正在查看的作品优先）；把识别页从作品工作区独立出来——识别不属于任何作品。
  草案已完成第二轮修订、清掉全部待决策项，待维护者批准；见
  `0.4-artwork-database-upgrade-scheduling-and-identification-plan-draft-2026-10-22.md`。
- **C2PA 验证口径（2026-11-04）**：升级到 `c2pa 0.91.10` 后，`Reader`/`Builder` 固定使用
  `verify_trust = false`、`verify_after_sign = false` 的上下文，并显式补回 C2PA/文档签名等
  EKU。证书由用户自带、通常不在公共信任列表里，0.91 会把 `signingCredential.untrusted`
  判为失败；本应用的信任模型是「本地记录 + 签名完整性」，`Valid` 不宣称 CA 信任。
  发布回读仍由 `validate_signed_manifest` 逐项核对声明。旧清单（≤0.90）由
  `authenticity/legacy.rs` 只读识别，状态固定 `LegacyUnverified`。
- **签名**：Authenticode 签名仍无法进行。按 `docs/guides/release-policy.md`，未配置证书输入时
  允许未签名发布，但发布说明必须显著披露未签名状态及 SmartScreen 影响；签名相关的人工门槛项
  在签名可用前无法执行。
