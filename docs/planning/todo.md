### 架构审查整改 B2 右键菜单

作品树（含「新建」菜单）与历史节点菜单已统一到共享 `ContextMenu`；以下四项需在 Tauri
宿主里手工确认：

- 键盘：菜单打开后按 Escape 关闭，焦点回到触发按钮或合理位置。
- 滚动：滚动任意祖先容器时菜单关闭，且不随内容错位。
- 缩放：窗口缩放或缩放级别变化时菜单关闭或重新定位，不超出视口。
- 定位：靠近窗口边缘打开时不越界；菜单自身滚动时仍可点到全部条目。

### 同仓库写入排队（alpha2 遗留）

跨进程拒绝、强杀不留锁与持锁期间只读可用已由 `stress_concurrency` 覆盖，只剩界面观感：

- 同进程写者排队而非互报「另一个进程写入」、自动备份进行中保存/退出画板；实施记录见
  `archive/repository-write-lock-plan-2026-10-18.md`。需要慢速备份目标（网络盘/U 盘），或让保存
  与自动备份真正重叠后再观察 busy 文案。

### 切换作品的画板交接

- 素材板里有未保存改动时切换作品：不弹错误，页头下方短暂出现「正在后台保存 1 块画板的改动」
  后消失；切回去内容仍在。扫同一作品的两块画板之间来回切也走同一条路径。该提示存在时间很短，
  需要录屏或更慢的保存路径才能捕捉。
- 把仓库目录改成只读（或写满磁盘）后做一次画板编辑再切换：出现常驻的「N 块画板的改动还没写进
  仓库：…」+「重试」，画布与作品一致；恢复可写后点「重试」即写回、提示消失。要验证该分支，需要
  一种「数据库仍可打开、但保存时写入失败」的条件（例如真实磁盘写满）；整仓 ACL、只锁数据库与
  只锁画板目录分别会在更早的仓库校验、SQLite 打开或数据库布局写入阶段走别的分支。

### 素材板文字格式（延期）

字体栏目前只做有效字号、颜色与对齐。粗体、斜体、下划线需要在 `pin_board_texts` 增加列，
**等下一次仓库 schema 升级（0.4 或后续版本）时顺带做**：新增列、补 vN→vN+1 迁移，并同步接入
`textLayout.ts` 的度量/栅格化、Rust 文字载荷 DTO、字体栏开关与测试。不要为本项单独切一次 schema。
计划正文见 `archive/pin-board-text-inline-editing-plan-2026-10-24.md`。

## 维护者决策记录

仍然生效的决策：

- **分支模型**：`main` 固定为 0.2 发布线（`v0.2.0`，指向 `0be6224`），不再接收 0.3 改动；
  `dev` 从 `0be6224` 创建，作为 0.3 开发线。历史与发布记录见
  `archive/handoff-log-2026-10-18.md`。
- **0.3 版本线**：alpha1–alpha6 未打标签；beta.1 已于 2026-10-25 打标签并作为 Pre-release 公开，
  是 0.3 线当前最后一版。
  逐批范围与落实口径见 `archive/handoff-log-2026-10-18.md` 至
  `archive/handoff-log-2026-10-25.md` 与两份计划正文；0.3 因此有两次迁移（alpha3 的 v4 → v5
  与 alpha5 的 v5 → v6）。
- **快速命中计数改为自适应强制全量（2026-10-21）**：不采用固定 N。阈值按本轮到期队列长度与分支
  文件大小分档，并以 7 天为年龄上限；后台忙时把全量确认推迟到队列消化后，长间隔下允许阈值小于 8。
  数值与实测依据见 `docs/modules/history-and-backup.md` 的「调度」。
- **提交路径不再复检旧快照（2026-10-20）**：`validate_head_snapshot` 从提交路径移除，只为它服务的
  `repair_head_snapshot` 一并删除；旧快照的完整性交给恢复、`verify_history_node` /
  `scrub_history` 与空闲完整性检查（默认关闭）。维护者明确接受「该开关默认关闭时这层体检实际
  不生效」这个代价，也不采用按计数抽检。实测见
  `archive/backup-scheduling-fix-plan-2026-10-20.md` §6.1 与 §6.4。
- **退出结算以 finalize/settlement 为准（2026-11-03）**：`pin-board settle flush finished` 只在退出时
  仍有排队快照时打印；空队列会在 `pendingSettle.ts` 的 `flushPendingSettle` 提前返回。正常关窗路径
  的验收口径改为 `pin-board finalize start/done` 与 `shutdown settlement finished: outcome=ok`，
  不再把缺少 flush 行视为缺陷。
- **缩略图格式扩展只做第一批（2026-10-20）**：`.sai2`、`.procreate` 与无魔数的 `.tga` 已实施，
  kra/krz、ora、cbz、ooxml、odf、blend、svg、exr/hdr/qoi/ff/pnm 暂不做，`supports_preview` 不登记
  它们；不引入 Windows Shell 缩略图接口。依据见
  `archive/thumbnail-format-expansion-plan-2026-10-20.md`（§2、§9）。
- **作品独立数据库、仓库升级、控制总线与识别页独立化列入 0.4（2026-10-22）**：把每个作品拆成
  独立数据库以获得跨作品并行写；把「打开旧仓库即静默迁移」改成显式升级流程（升级页阻断其它
  操作、说明风险、可选不升级、进度可见、中断不损坏原仓库）；控制总线按作品并行并把长任务
  并发数量管住（毫秒级微任务直通，不排队、不参与调度决策；主窗口只看一个作品，渲染引擎
  仍只有一份，正在查看的作品优先）；把识别页从作品工作区独立出来——识别不属于任何作品。
  草案已完成第二轮修订、清掉全部待决策项，待维护者批准；见
  `0.4-artwork-database-upgrade-scheduling-and-identification-plan-draft-2026-10-22.md`。
- **签名**：Authenticode 签名仍无法进行。按 `docs/guides/release-policy.md`，未配置证书输入时
  允许未签名发布，但发布说明必须显著披露未签名状态及 SmartScreen 影响；签名相关的人工门槛项
  在签名可用前无法执行。
