## 素材板笔迹与图层（0.3 alpha5 计划，2026-10-20 记入）

计划正文与实施记录见 `archive/pin-board-strokes-plan-2026-10-20.md`，分五个阶段：schema v6 与存储层、
SDF 渲染管线、绘制交互与工具、编辑与图层可见性、压感与性能验收。**阶段 1–5 均已落地**（含采样管道、
压感、合并事件、逐段裁剪与超扫边距、无头批量命令与 H4/H5/P9 测试），**只剩阶段 5 的人工验收与发布前
压力测试**。

阶段 1 已定的结论：

- **创建命令的几何参数**：`Uint8Array` 能直接作为命令参数——IPC 的 JSON 序列化把它还原成数字数组
  （与剪贴板图片的 `bytes` 同一通道），因此不必退到二进制通道，`MAX_STROKE_POINTS` 保持 4096
  （单笔上限约 75 KB JSON）；整板读取仍走 `read_pin_board_strokes` 的二进制载荷，前端零 JSON 解析。
- **搭车三列**：`branches` 的检查耗时、检查方式与快速命中计数均已随 v6 建列并接线——成功检查后
  写库、重启后恢复耗时、分支状态行显示方式与耗时；快速命中计数驱动「按当前负载强制一次全量」
  的主动审计（见 `docs/modules/history-and-backup.md` 的「调度」）。

需要维护者确认或验收的点：

- **渲染观感**（阶段 2）：在有可用 WebGPU 适配器的机器上打开含笔迹的画板，逐档缩放到 10%–800%
  确认五种工具（自由笔、直线、箭头、矩形、椭圆）的边缘干净、细笔不断裂；选中笔迹时包围框描边与
  图片一致；画板里只有笔迹时不出现「正在加载」或红色失败占位框；没有适配器时仍是常驻的「素材板
  不可用」说明。阶段 3 之后可以直接用工具画出来，不必再手工造数据。
- **修订后的复测**（阶段 3，2026-10-20 记入）：连续快速画多笔不再报「画板已被其他窗口修改」、每一笔
  都落库，重开画板后笔迹仍在；绘制工具下画完不出现包围框，切回选择工具后仍能拖动/旋转/缩放笔迹；
  浮动工具条在画布下方居中，`T` 单独负责收起/展开（条上与主工具栏都没有显隐按钮），收起后仍可用
  快捷键换工具，全屏下仍可用；线宽文字保持单行、滑条与数值框同步；取色浮层能正常弹出，且在窗口
  较窄或全屏下不越界、不被工具条裁掉。手感与落库观感（预览与落库后的位置、粗细、颜色一致，松手不闪
  空白，Shift 四种约束，拖拽不足 3 像素不产生条目）一并确认。粗箭头的三角会略微超出选中框，这是已知
  观感细节（见 `archive/pin-board-strokes-plan-2026-10-20.md` 阶段 3 的落地结论），验收时一并判断
  要不要改箭头尺寸。

- **图层可见性**（阶段 4，2026-10-20 记入）：分层显示的显示效果已人工验证通过。按反馈改成画布
  左上角的浮动面板后，复测面板在窄窗口与全屏下的位置、收起/展开是否顺手、四个开关的观感（隐藏的整行
  变淡、按钮高亮），以及面板不遮住画布内容；仍待确认被隐藏的内容点不到、框不到、`Ctrl+A` 也选不到、
  不会被导出；隐藏标注层后「重置视图」不会缩放到空白；先选中某层里的条目再隐藏该层，选中被取消；
  选中笔迹时右键菜单的图层三项置灰并给出说明；切走画板再切回，四个开关保持（重启应用后回到全部显示，
  这是预期）。另请判断两处已定行为是否接受：**混选（图片 + 笔迹）时整组拒绝改图层**（而不是只改图片），
  以及**新条目落进隐藏层时自动打开该层**。

- **采样与压感手感**（阶段 5，2026-10-21 记入）：用真实数位笔确认落库前后的位置、粗细、颜色一致，
  两端 taper 自然、尖角不被抹圆、快速划线不断裂；驱动处于「鼠标模式」时 `pressure` 恒为 0.5，
  应整笔等宽（设备没给数据，不是功能坏了）；无压感设备的轻描不应反而最粗。预览与落库的压感判定
  现在是同一条件（指针是笔且收到过非零压感），重点确认松手不出现「突然变粗/变细」。
- **性能指标**（阶段 5，2026-10-21 记入）：500 笔 60 fps、2000 笔 ≥ 45 fps、5000 笔 ≥ 20 fps；
  打开画板对应 < 300 ms / < 600 ms / < 1.2 s；Rust 侧 5000 笔批量读取 < 200 ms、批量写入 < 500 ms。
  60 fps @ 500 笔是目标而非承诺，达不到时如实报告瓶颈，不调低目标收场。开发构建可用
  `__lilithPinBoardStrokeProbe()` 先量 CPU 侧采样/编码/缓冲成本，帧率仍需在真实适配器上手工看。
- **全套压力测试**：除 `manual` 档外的全套已于 2026-10-21 在 release 无头构建跑完并全部通过
  （H4/H5 与 P9 发布档首跑；P9 数值已写进 `tests/perf-baseline.json`，评注见
  `docs/user/stress-test-report.md` 的「2026-10-21 复跑摘要」）；0.3 发布前只剩 `manual`
  8 GiB 档，由维护者显式安排。

## 手动重查分支的耗时确认（2026-10-21 记入）

  后消失；切回去内容仍在。扫同一作品的两块画板之间来回切也走同一条路径。
- 把仓库目录改成只读（或写满磁盘）后做一次画板编辑再切换：出现常驻的「N 块画板的改动还没写进
  仓库：…」+「重试」，画布与作品一致；恢复可写后点「重试」即写回、提示消失。
- 退出应用（后台还有未写回的快照时）：日志里 `pin-board settle flush finished` 的 `remaining=0`，
  下次启动画板内容是最后看到的样子。

  文件大小分档，并以 7 天为年龄上限；后台忙时把全量确认推迟到队列消化后，长间隔下允许阈值小于 8。
