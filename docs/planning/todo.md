## 一、待实现 / 待补强

| 优先级 | 事项 | 现状 | 影响 |
| --- | --- | --- |
| P1 | 接入素材板运行时变更结算流程 | `src/modules/pin-board/lifecycle.ts` 已提供 `preparePinBoardRuntimeChange`，但当前没有调用方；渲染器 `destroy()` 对结算使用 fire-and-forget。仓库切换、关闭或工作区卸载时可能先释放仓库，再完成最后一次保存 | 最后编辑可能保存失败且用户只看到卸载；应在仓库切换/关闭边界等待结算，并在失败时阻止切换或明确提示 |
| P2 | 长任务与灾备调度并行的降级策略 | 纹理读取持共享读租约；灾备/扫描持仓库操作锁期间画板浏览可继续但画板写入会等待 | 实测卡顿不可接受时再评估，例如提供缩略图缓存或更明确的写入等待状态 |
| P2 | 超期临时目录清理 | `repository/temp` 中会遗留认证预览会话目录（观察值约 40 MB） | 长期使用会累积占用；可考虑打开仓库时按创建时间清理超期临时目录，并保留当前活动会话 |
| P2 | 历史长操作的结果刷新与批量化 | 当前精简由前端逐节点调用 `compact`；中途取消或某一步失败时依赖轮询刷新，用户难以知道已完成到哪一步 | 大量节点操作会产生多次锁竞争和刷新；可提供一次性批量命令，返回完成数量、取消点和剩余节点 |
| P2 | 同仓库多进程并发缺乏防呆 | 应用层的仓库互斥与读写租约只在进程内有效（`AppState`），跨进程只剩 SQLite 的 WAL + `busy_timeout`；单实例插件只覆盖 GUI 入口，无头入口不启动 Tauri 应用、不受其约束 | 数据库层不会损坏（事务 + `synchronous = FULL`），但旧版本进程会因 schema 迁移把仓库判为不可用、设置文件为"最后保存者胜"、并发提交与清理队列重放的业务层竞态未设计未测试；应为无头命令与未来的清理扫描入口加仓库哨兵锁（打开前检测是否已被占用），并在模块文档写明"不支持同仓库多进程写入" |

## 二、待验证 / 待人工验收

按 `docs/guides/release-policy.md` 的"人工门槛"，以下项目对 `0.2.x` 仍未执行。可程序判定的
部分已由发布前的自动化压力测试接管（`src-tauri/tests/`，见 `docs/guides/validation.md` 与
`docs/guides/stress-test-report.md`），**保留人工复核手感**；界面视觉、交互手感与桌面集成
仍由维护者手工验收：

- **各处理阶段的取消边界**（提交、恢复、精简、检查点、整仓灾备、认证签名）——
  **已自动化覆盖**（A 组 28 次受控取消 + 认证签名的渲染/编码/签名三阶段由 G3 覆盖），
  保留人工复核手感；
- **损坏文件的恢复路径**（snapshot/delta 缺失或摘要不匹配）——构造损坏文件与摘要不匹配的
  部分**已自动化覆盖**（R 组端到端，叠加 `backup/worker.rs`、`backup/restore.rs` 单测）；
  崩溃窗口由 B 组、SQLite 事务中途崩溃由 B4、孤儿回收由 B5 覆盖。
  **异常 RFC 3161 时间戳服务的失败与超时行为仍需人工**；
- **画板 DDS 损坏、缺失、孤儿文件**——**已自动化覆盖**（H1 双向检查四类计数、H2 孤儿回收）；
  结算/仓库切换期间的保存失败恢复仍需人工；
- **极端大文件与高像素压力的错误恢复**——维护者已在 2 GiB 工作文件与大像素图片下日常使用
  正常；**已自动化覆盖**（大文件端到端 C 组、高像素 G1/G2、损坏恢复 R 组）；
- **断电持久性**——**不做自动化验证**：`Child::kill()` 不触及 OS/磁盘缓存与目录项落盘，
  结构上无法覆盖「断电后已提交数据是否仍在」；由 OS/磁盘与 `synchronous = FULL` 声明保证。

**任务调度总控与空闲链路校验批次（2026-10-04 落实，待人工验收）**——代理只做程序化断言，
以下界面与交互由维护者手工确认：

- 空闲校验进行中触发取消（用户操作进入、托盘暂停、显式退出）；
- 校验失败警告的展示、详情展开与“重新校验此分支”清除路径；
- 快速检查分支与空闲校验的组合行为（快速记未变化后新链仍被校验）；
- 大链校验期间前台操作（提交、发布、恢复）的响应性；
- 校验失败后继续手动提交是否正常（失败不阻断）。

**统一清理体系批次 A–F（2026-10-04 落实，待人工验收）**——批次 A、B 为后端清理路径改动
（画板结算、分支/子树删除、取消检查点、提交释放旧 snapshot、修复 head snapshot、
精简改接），批次 F 把清理账本与未引用扫描暴露到设置页；代理只做程序化断言，以下由维护者确认：

- 清理失败只在日志与 `pending_file_cleanup` 队列中体现，上述命令的成功/失败文案与
  交互与改动前一致；
- 设置页「仓库与备份」页「文件清理」区：待清理队列列表（路径、原因、上次失败原因与
  最近尝试时间）、单条与全部重试、未引用文件扫描按钮及扫描结果确认清理对话框的呈现与交互；
- 仓库完整性检查报告在发现画板 DDS 缺失/损坏/孤儿时的警告文案；
- 创建备份成功文案在回收了残留暂存目录时的附加说明（仅在确有残留时出现）。
