## 二、待验证 / 待人工验收

按 `docs/guides/release-policy.md` 的「人工门槛」，以下项目对 `0.2.x` 仍未执行。可程序判定的
部分已由 `src-tauri/tests/` 的压力测试接管（见 `docs/guides/validation.md` 与
`docs/user/stress-test-report.md`），其中**八组便宜的分组已进 Windows CI**；保留人工复核手感；
界面视觉、交互手感与桌面集成仍由维护者手工验收。

已自动化覆盖、保留人工复核手感：

- 各处理阶段的取消边界（提交、恢复、精简、检查点、整仓灾备、认证签名），含**大文件**提交中途
  取消与强杀（C7）；
- 损坏文件的恢复路径（snapshot/delta 缺失或摘要不匹配），含**主库文件本身**损坏（误写/清空）
  时的干净失败（R3/R4），以及**随机化单点损坏逐文件、多种子扫描**（R5）与画板 DDS 的
  结构性损坏 / 随机改写（R6）；
- 画板 DDS 损坏、缺失、孤儿文件；
- 极端大文件与高像素压力的错误恢复；
- **解析器的畸形输入模糊**（容器 / DDS 头 / C2PA 清单 / 设置文件，见 `src/fuzz_support.rs`），
  断言不受信任的字节不能换来 panic、越界或无界分配；
- **输入域极值**（K 组）：非 ASCII 与 emoji 标题逐字符往返、标题长度按字符而非字节计数、
  空白与零宽字符的处理、非 ASCII / 含空格 / 深层路径的端到端可用、相对路径与工作区之外
  路径的明确拒绝；
- 无头入口的仓库写并发（哨兵锁明确拒绝第二个写进程；被强杀不残留锁），**多操作交错**
  （长写持锁时只读命令仍作答且看到一致状态：提交、整仓灾备、精简三类；并发读互不阻塞；
  真并发的「精简 + 全库校验」不损坏仓库——其中暴露的错误可读性问题见第一节 P2），
  以及进程内读租约（`app/settings.rs` 单测）；
- 核心算法性能基线（节点链、认证、画板 DDS、库树与搜索、整仓灾备、清理扫描；`stress_bench`，
  默认只记录、可经严格模式比对）。

仍需人工：

- 任务调度总控与空闲链路校验批次的界面项：空闲校验进行中触发取消、校验失败警告的展示与
  「重新校验此分支」清除路径、快速检查与空闲校验的组合、大链校验期间前台操作的响应性、
  校验失败后继续手动提交是否正常。
- 2026-10-17 五项安全与一致性修复中涉及界面的部分（代码与自动化测试已完成）：
  - 设置页「仓库与备份」→「文件清理」：外部文件条目显示完整路径、所属作品与期望 SHA-256，
    「确认删除…」弹出滑动确认而不是点击即删；队列里只剩外部条目时「全部重试」为禁用；确认后
    条目出队。可用「认证发布过程中断」制造一条外部条目的残留，或直接观察既有队列。
  - 工作文件被改成网络位置（如 `\\nas\share\x.psd`）后：分支记录显示「工作文件位于网络位置，
    已跳过自动备份」，自动备份不再触碰该路径，手动提交仍可用；设备命名空间路径（`\\.\...`）
    在手动提交与「打开所在文件夹」时报明确错误，且带这类路径的仓库打不开。
  - 素材板：从资源管理器复制图片文件后「导入图片」仍可用（路径由剪贴板读取命令授权）；粘贴
    纯文本路径不再导入并提示「未由文件选择器授权」；导出目录选到仓库内部时报明确错误。

**怎么测**（2026-10-16 补，供维护者执行；通过并归档后从本节删除）：

- 空闲校验的前提容易误判：它只在仓库空闲（无前台命令、无待处理手动提交、托盘未勾「暂停所有
  自动备份」）且 head 提交已过 **10 分钟**（`IDLE_VERIFY_DELAY_MS`）时自动跑，每轮一个分支，
  想快点测就用较早提交的分支。要制造失败：先备份 `artworks/<artwork-id>/snapshots/` 下
  **最新那个 snapshot**（即 head 节点的），改名或删除后等校验失败并观察历史页的警告；再改回
  原名、点「重新校验此分支」，验证警告清除且随后校验通过。提交会清空 `verify_error`，所以
  带着失败警告继续手动提交应当正常成功。第 1、3、4 项分别测：校验运行期间启动前台长命令
  （恢复/精简/整仓灾备/全库扫描）时后台是否让位、历史页的取消按钮是否仍只属于「本页自己的
  操作」；「快速检查」与空闲校验互不吞掉运行机会；设置页跑仓库完整性扫描期间切页面与浏览
  素材板是否保持可响应、中途取消能否停在节点边界。

不做自动化：

- 断电持久性——`Child::kill()` 不触及操作系统与磁盘缓存、也不保证目录项落盘，该保证由操作
  系统、磁盘与 SQLite `synchronous = FULL` 声明承担。

## 三、维护者决策记录

2026-10-16 维护者就下列事项给出结论；这些口径已于 2026-10-17 全部落地（代码、自动化测试与
模块文档），涉及界面的部分待人工验收（见第二节）。

- **标签与版本推进**：本阶段**不打任何标签**（`rc.3` 与 `0.2.0` 都不新建标签），目前不考虑标签
  这件事；版本切分与打标签一并后议，不再与人工验收捆绑。`v0.2.0-rc.2` 仍是最近一个已打标签的
  候选版，工作版本为 `0.2.0-rc.3`。
  `docs/guides/release-policy.md` 的干净 Windows 用户环境桌面验收仍是切版本/打标签时的必过项，
  只是现在不是前置工作。
- **审查两条 P1 的修法**：路径校验按「读取侧结构校验 + 无人值守使用点跳过网络/设备路径、
  打开不因网络路径拒绝」的口径；外部清理按「移出启动自动重放 + 设置页逐条显式确认」。完整口径
  见 `docs/modules/library.md` 与 `docs/modules/history-and-backup.md`。
- **`scrub × compact` 并发错误**：采用「只让内容级全库校验在写哨兵被持有时明确拒绝」的方案，
  轻量只读命令的既有承诺不变；不采用「`scrub` 重读节点集继续」。
- **素材板路径授权（P2）与 TrustMark 模型完整性（P3）**：两条都纳入审查两条 P1 的同一批
  一并修，不推迟到 0.3。
