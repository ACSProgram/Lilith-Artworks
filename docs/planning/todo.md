| P2 | 超期临时目录清理 | `repository/temp` 会遗留认证预览会话目录（观察值约 40 MB） | 长期使用会累积占用；可考虑打开仓库时按创建时间清理超期临时目录并保留当前活动会话 |
| P2 | 历史长操作的结果刷新与批量化 | 精简仍由前端逐节点调用 `compact`；取消已改为前端批级标记（逐节点循环启动下一个节点前检查，命中即停止并刷新历史），某步失败仍靠命令报错与轮询刷新 | 大量节点操作会产生多次锁竞争；可提供一次性批量命令，返回完成数量、取消点与剩余节点 |

| P2 | 跨画板保留纹理（切回更快） | 按「切换即全释放」策略，疯狂切换会产生 2–4 s 的异步纹理装载批次（含 DDS 解码与磁盘 IO 等待，非主线程阻塞） | 若要更顺滑的切回，可跨画板保留纹理复用，但常驻内存更高、预算管理更复杂 |
| P2 | 同仓库多进程并发缺乏防呆 | **无头侧已加跨进程哨兵锁**（`src-tauri/src/repository_lock.rs`，SQLite `BEGIN IMMEDIATE`，只对会写仓库的无头命令生效，由 `stress_concurrency` / I 组覆盖）；GUI 侧仍只有单实例插件 | 无头与无头已互斥，且强杀不残留锁（锁由内核在句柄关闭时释放）；**GUI 与无头同时写同一仓库仍不受保护**。下一步可让 GUI 也读取同一把锁，或把哨兵锁下移到仓库打开处。模块文档的「不支持同仓库多进程写入」说明仍待补 |
| P2 | 全库校验与精简并发时给出难以理解的错误 | `stress_concurrency` J5 实测：`compact` 与 `scrub` 真正并发时（4 轮里 1 轮命中），`scrub` 以「找不到历史节点」失败。`scrub` 是只读命令、不在哨兵锁覆盖范围内，因此两者之间没有互斥，只靠 SQLite 快照隔离与文件系统语义 | 不损坏数据（同轮结束后 `verify` + `scrub` 通过、每个节点仍逐位恢复，失败也是干净退出），但用户在精简进行中跑「全库校验」会拿到一个与原因无关的错误。修法二选一：① 让 `scrub_history` 在节点被并发移除时重读节点集合并按新状态继续；② 让全库级只读命令在哨兵锁被持有时给出明确提示（「仓库正在被写入，请稍后重试」）。两种都属于行为改动；**已定口径**：采用方案②——**只**让内容级全库校验（`scrub`）在写哨兵锁被持有时明确拒绝并提示「仓库正在被写入，请稍后重试」，`verify` 与 `list-*` 等轻量只读命令**保持**「写进程持锁期间照常作答」的既有承诺不变（J1/J2 已断言该行为，不得回退）。不采用方案①：让 `scrub` 在节点被并发移除时重读节点集继续，等于校验一个正在变动的目标，语义不清，且会掩盖真实的并发窗口。落地时 J5 的断言改为接受这次**有意义的拒绝**，并把它计入报告而非边界项 |

仍需人工：

- 任务调度总控与空闲链路校验批次的界面项：空闲校验进行中触发取消、校验失败警告的展示与

**怎么测**（2026-10-16 补，供维护者执行；通过并归档后从本节删除）：

- 空闲校验的前提容易误判：它只在仓库空闲（无前台命令、无待处理手动提交、托盘未勾「暂停所有
  自动备份」）且 head 提交已过 **10 分钟**（`IDLE_VERIFY_DELAY_MS`）时自动跑，每轮一个分支，
  想快点测就用较早提交的分支。要制造失败：先备份 `artworks/<artwork-id>/snapshots/` 下
  **最新那个 snapshot**（即 head 节点的），改名或删除后等校验失败并观察历史页的警告；再改回
  原名、点「重新校验此分支」，验证警告清除且随后校验通过。提交会清空 `verify_error`，所以
  带着失败警告继续手动提交应当正常成功。第 1、3、4 项分别测：校验运行期间启动前台长命令
  （恢复/精简/整仓灾备/全库扫描）时后台是否让位、历史页的取消按钮是否仍只属于「本页自己的
  操作」；「快速检查」与空闲校验互不吞掉运行机会；设置页跑仓库完整性扫描期间切页面与浏览
  素材板是否保持可响应、中途取消能否停在节点边界。

不做自动化：

- 断电持久性——`Child::kill()` 不触及操作系统与磁盘缓存、也不保证目录项落盘，该保证由操作
  系统、磁盘与 SQLite `synchronous = FULL` 声明承担。

## 三、维护者决策记录

2026-10-16 维护者就下列事项给出结论，均**只改口径、未改产品代码**；实施状态见第一节。

- **标签与版本推进**：本阶段**不打任何标签**（`rc.3` 与 `0.2.0` 都不新建标签），目前不考虑标签
  这件事；版本切分与打标签一并后议，不再与人工验收捆绑。理由是先把第一节的口径落地、把第二节

  `docs/guides/release-policy.md` 的干净 Windows 用户环境桌面验收仍是切版本/打标签时的必过项，
  只是现在不是前置工作。
- **第一节两条 P1 的修法**：路径校验按「读取侧结构校验 + 无人值守使用点跳过网络/设备路径、
  打开不因网络路径拒绝」的口径；外部清理按「移出启动自动重放 + 设置页逐条显式确认」。完整口径
  写在第一节对应行内。
- **`scrub × compact` 并发错误**：采用「只让内容级全库校验在写哨兵被持有时明确拒绝」的方案，
  轻量只读命令的既有承诺不变；不采用「`scrub` 重读节点集继续」。
- **素材板路径授权（P2）与 TrustMark 模型完整性（P3）**：两条都纳入第一节两条 P1 的同一批
  一并修，不推迟到 0.3。
