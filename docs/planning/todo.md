# 待办清单

本文件是本项目**唯一**的未完成事项清单：尚未实现、尚未验证或需要维护者决策的内容都记在这里。
已完成的批次写归档（`archive/README.md`），当前批次的执行状态写 `current-handoff.md`。

更新时间：2026-10-03（对应版本 `0.2.0-alpha.3`；清单内容仍为 2026-09-18 素材板与历史模块审查结论）

## 一、待实现 / 待补强

| 优先级 | 事项 | 现状 | 影响 |
| --- | --- | --- |
| P1 | 结算画板时改用提交后文件清理 | `src-tauri/src/pin_board/repository.rs` 的 `finalize_board` 在 SQLite 事务尚未提交时直接删除已标记删除图片的 DDS。若数据库提交随后失败，记录会回滚而实体文件已经消失 | 可能形成“数据库仍有图片记录但 DDS 丢失”的不可逆不一致；应改为事务提交后清理，失败进入已有的待清理队列 |
| P1 | 接入素材板运行时变更结算流程 | `src/modules/pin-board/lifecycle.ts` 已提供 `preparePinBoardRuntimeChange`，但当前没有调用方；渲染器 `destroy()` 对结算使用 fire-and-forget。仓库切换、关闭或工作区卸载时可能先释放仓库，再完成最后一次保存 | 最后编辑可能保存失败且用户只看到卸载；应在仓库切换/关闭边界等待结算，并在失败时阻止切换或明确提示 |
| P1 | 历史文件清理失败改为可观测、可重试 | `src-tauri/src/app/workflows.rs` 删除分支时对历史 snapshot/delta 的 `remove_file` 结果直接忽略；画板清理已有 `pending_file_cleanup`，历史清理没有同等记录 | 磁盘空间会静默泄漏，用户无法知道哪些历史实体仍未删除；应记录相对路径、失败原因和下次重试状态 |
| P2 | 任务调度总控与空闲链路校验（alpha3 落实） | 规划见 `docs/planning/task-control-plan-2026-10-03.md`：BackupState 任务类型与取消路由、schema v4 校验状态、调度器两级选择、失败警告面 | 补上快速检查不校验 head snapshot 的完整性缺口；alpha.2 收尾验收完成后按批次 A–D 实施 |
| P1 | 仓库完整性扫描覆盖画板 DDS 文件 | 设置页“仓库完整性”目前只扫描历史链（snapshot/delta）与认证受控文件（最终成品、认证副本）。整仓灾备的清单会对 `boards/**/*.dds` 记录 SHA-256，但普通扫描不校验其内容语义 | 画板纹理损坏只能在恢复或实际读取时暴露；扫描至少应校验路径归属、DDS/BC7 头、尺寸、长度和摘要 |
| P1 | 增加画板实体与 SQLite 的双向清理检查 | 现有导入失败有临时文件回滚，但异常退出、手工复制或历史迁移仍可能留下无记录 DDS；读取路径只按约定的 `image_id.dds` 查找，未报告孤儿文件 | 仓库会持续积累无法使用的文件，备份体积增大；完整性检查或打开仓库时应报告并提供安全清理入口 |
| P2 | 分支工作文件路径的清空约束人工验收 | 当前允许清空工作文件路径，但同一 Artwork 只能有一个分支留空（`source_path_key` 非空且唯一） | 第二个分支清空会被拒绝并提示；需要人工确认提示文案、分支选择变化和保存失败后的表单回滚 |
| P2 | 长任务与灾备调度并行的降级策略 | 纹理读取持共享读租约；灾备/扫描持仓库操作锁期间画板浏览可继续但画板写入会等待 | 实测卡顿不可接受时再评估，例如提供缩略图缓存或更明确的写入等待状态 |
| P2 | 超期临时目录清理 | `repository/temp` 中会遗留认证预览会话目录（观察值约 40 MB） | 长期使用会累积占用；可考虑打开仓库时按创建时间清理超期临时目录，并保留当前活动会话 |
| P2 | 历史长操作的结果刷新与批量化 | 当前精简由前端逐节点调用 `compact`；中途取消或某一步失败时依赖轮询刷新，用户难以知道已完成到哪一步 | 大量节点操作会产生多次锁竞争和刷新；可提供一次性批量命令，返回完成数量、取消点和剩余节点 |

## 二、待验证 / 待人工验收

按 `docs/guides/release-policy.md` 的"人工门槛"，以下项目对 `0.2.x` 仍未执行：

- 极端大文件与高像素压力的内存、取消、退出与错误恢复（使用正式支持上限附近的图片与工作文件）；
- 各处理阶段的取消边界（提交、恢复、精简、检查点、整仓灾备、认证签名）；
- 异常 RFC 3161 时间戳服务的失败与超时行为；
- 损坏文件的恢复路径（snapshot/delta 缺失或摘要不匹配）；
- 画板 DDS 损坏、缺失、孤儿文件以及结算/仓库切换期间的保存失败恢复；
- 普通用户账户安装、Authenticode 签名与时间戳验证；
- 第三方工具回读 C2PA，并用随包模型验证 TrustMark 实图；
- 从上一公开候选版执行安装升级与卸载。
