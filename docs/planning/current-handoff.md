## 清单维护规则

- `P1`、`P2` 只保留尚可由代码、配置或自动测试推进的问题；已实现并通过匹配的自动验证后，直接从开发清单删除，同时把已经生效的契约写入对应 `docs/modules/` 或 `docs/architecture/` 文档。
- GUI 操作、真实证书或第三方服务、安装升级、签名产物、长时间压力与峰值内存测量统一放在“待人工验证清单”，不重复出现在开发问题中，也不计入当前代码阶段的剩余量。
- 人工验证未完成不表示代码问题仍未修复，但仍可作为候选版或正式版发布门槛；验证通过后的证据归档到 `docs/planning/archive/`，并从当前清单删除。
- 需要维护者作出产品、法律或密钥托管决定的事项单独列出；在决定作出前，代码可以继续推进不依赖该决定的部分。

- GitHub 私密漏洞报告当前未启用；`SECURITY.md` 已增加不泄露技术细节的公共联系请求兜底，但正式版前仍必须提供并实测真正的私密渠道。

## 已有基础

- 前端领域 API、应用层跨模块编排和 Rust storage/domain/workflow 边界总体清楚，普通打开仓库不会隐式创建数据库。
- SQLite 已启用 WAL、外键、FULL synchronous 和 busy timeout；历史提交使用 no-clobber 发布、摘要和失败清理，认证副本已有持久 cleanup intent。
- 设置页整仓灾备在共享运行锁和仓库 lease 内 checkpoint WAL，复制后独立 scrub、生成逐文件 SHA-256 清单并以临时 bundle 原子发布；恢复副本不依赖原仓库目录。
- 私钥使用 `Zeroizing`，未写入数据库、设置或日志；前端未获得通用文件读写权限，CSP 与 dialog scope 基础较收敛。
- 历史树事务和前端纯模型已有基础测试，CI 能覆盖前端构建、前端测试、Rust 格式和库测试。

## P1：剩余代码与自动测试

当前原 P1 开发组已完成 `P1-01`，剩余 7 组。按任务数是 `1/8` 完成；按工作量粗估，代码与自动测试约完成 15%，大文件资源边界、迁移矩阵、真实认证 fixture 和发布工程仍是主要工作。人工验证不计入该百分比，但在新候选版发布前仍需另行完成。

- [ ] **P1-03 真实认证 fixture。** 增加真实 C2PA/TrustMark fixture，覆盖合格验证状态、record ID/TrustMark ID/声明匹配，以及文件替换、无效状态和声明不匹配的 fail-closed 行为。
- [ ] **P1-05 大文件内存上限。** delta 恢复会同时持有完整压缩数据和无上限解压结果；认证管线和隐藏发布页会创建多份全分辨率像素、JPEG 与 base64 data URL。改为流式或有硬上限的解压，限定像素、边长、压缩后/解压后字节数，发布页仅在激活时加载并使用缩略图或分块处理；用小型合成压缩炸弹和超限图片头自动测试稳定拒绝及错误分类。
- [ ] **P1-07 发布状态与 TrustMark 身份。** 发布元数据和预览读取处于同一异常路径，预览损坏会让已发布分支显示为未发布并隐藏取消入口；自动生成的 TrustMark ID 还会跨分支和发布复用。先提交发布元数据，再独立加载/重试预览；取消发布始终可达；将 watermark ID 绑定到分支或一次待发布操作，并在切换、禁用和成功发布后清空。
- [ ] **P1-08 版本、迁移与旧标识。** 增加 v8→v9 自动迁移测试和迁移前备份；为 v4→v5、v7→v8 会删除认证记录的行为实现最低支持版本、导出/阻止升级提示和数据保留策略；实现 `art.lilith.artworks` 设置/日志/C2PA label 到 `com.lilith.artworks` 的一次性迁移或明确不兼容路径并补测试。发布前把 package、Cargo、Tauri 和锁文件统一升到 `0.1.0-rc.2`，不得移动 `rc.1` 标签。
- [ ] **P1-09 依赖与构建基线。** 将 Vitest 升到 3.2.6 或更高版本；把已 EOL 的 Node 20 CI 升到受支持的 Node 24 LTS；禁用或替换存在 `rsa` 风险的 PS256 路径并补回归测试。CI 增加官方 npm audit、RustSec、许可与 SBOM 门槛，并按 Windows 实际目标分类仅限其他平台的 Rust 告警。
- [ ] **P1-10 许可、安全渠道与可信产物。** 生成包含版本、版权和正文的 Windows 目标许可闭包，增加 About/Legal 入口；发布 workflow 从不可变标签构建 checksum、SBOM、许可包和 provenance，接入代码签名输入，并由 CI 解包断言法律文件与版本信息存在。
- [ ] **P1-11 发布测试矩阵。** 仍需为压缩炸弹/超大 delta、调度取消、真实 C2PA/TrustMark fixture、schema v1-v9、清理崩溃点和安装包资源增加自动测试。任何数据可靠性修复在故障注入和恢复演练通过前不得标记完成。

## P2：`0.1.0` 正式版之前必须完成

- [ ] **P2-01 崩溃一致性。** 检查点和精简的历史文件发布纳入持久 cleanup intent/reconciliation；对文件与发布目录提供平台等价的 durable publish 屏障，启动时处理临时文件和合法 orphan，文件删除失败不得吞掉。永久删除已提交元数据但后续清理失败时，要返回结构化的部分成功状态。
- [ ] **P2-02 授权、取消与安全退出。** 恢复目标、Artwork/fork 工作文件和仓库目录统一执行 dialog scope；ChunkFile 分块检查取消，C2PA/时间戳有取消和超时，退出过程显示明确状态且不长时间阻塞窗口事件线程。
- [ ] **P2-03 稳定读取与旧数据库选择。** 备份和最终成品复制不能只依赖 length+mtime，应验证文件身份及读取前后稳定性，或明确要求源文件关闭并检测违反条件。多个旧数据库候选必须稳定判定或要求用户选择；图归属语义检查仍需补齐。
- [ ] **P2-04 事务与设置前向兼容。** `create_branch` 的分支插入和起点 checkpoint 更新必须处于同一事务。高版本或无效 `settings.json` 进入只读/保留原文状态，托盘暂停和窗口状态捕获不得覆盖未知字段；增加降级启动后关闭窗口的回归测试。
- [ ] **P2-05 规模与查询。** 分支删除移除 O(n²) 路径，历史和认证记录分页；前端图计算预建索引并改为迭代实现，树和记录列表虚拟化。至少记录 10k、50k、100k 节点的加载、删除、内存和交互基线。
- [ ] **P2-06 前端错误恢复与事务反馈。** 批量精简部分成功后也刷新状态；历史初始加载失败显示错误和重试；应用增加顶层 ErrorBoundary；设置取消恢复实时主题/密度且异步加载不能覆盖用户草稿；证书路径不跨重启伪装为仍获授权。
- [ ] **P2-07 可访问性与输入。** 树支持方向键、Home/End 和 roving tabindex；区域选择提供键盘等价；对话框实现 focus trap、Escape 和焦点恢复；修正低于 WCAG AA 的次要文字对比度、过小字号、IME Enter 与视口外菜单。
- [ ] **P2-08 最终用户文档。** README 补充安装、升级前备份、schema 不可降级、卸载后数据保留、手动/自动更新渠道、支持范围和已知限制；模型来源记录精确下载 URL、上游 commit 与取得日期；确定并统一项目版权持有人和年份。

## 分阶段执行计划

1. **完整性自动化。** `P1-01` 的在线整仓灾备、复制后 scrub、SHA-256 清单和恢复副本自动测试已完成；下一步完成 `P1-03` 真实认证 fixture。代码退出条件是 fixture 能稳定覆盖成功与所有 fail-closed 分支。
2. **状态机与资源边界。** 完成 `P1-05`、`P1-07` 和 `P2-02`；代码退出条件是资源上限、取消/退出有界、发布状态和 TrustMark ID 生命周期均有自动测试。
3. **迁移与发布工程。** 完成 `P1-08` 至 `P1-11`；代码退出条件是唯一 `rc.2` 版本、迁移矩阵、许可闭包、审计门槛、SBOM、provenance 和安装包资源断言全部进入 CI。
4. **正式版质量。** 完成全部 P2 代码与自动测试；之后再集中执行下列人工验证，不在各开发问题中穿插人工步骤。
5. **正式发布。** 人工清单和维护者决策均闭环后，从已验收提交升为 `0.1.0`，创建不可复用的签名标签；由 release workflow 构建并发布，不使用开发机手工产物替换 CI 资产。
