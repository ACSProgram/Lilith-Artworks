## 数据所有权与边界

素材板是第五个领域模块，以 **Artwork 为单位**：一个 Artwork 内多块画板，平铺一层，无文件夹层级；列表顺序由 `sort_order` 决定，可在侧栏拖放调整。画板不纳入分支历史（不进增量提交、不参与恢复/裁剪）。

整仓灾备按仓库目录递归复制全部普通文件，`artworks/<artwork-id>/boards/**/*.dds` 因此已在副本与 `manifest.json` 逐文件 SHA-256 清单之内，恢复后的仓库可直接打开并读取画板；文字与笔迹条目没有实体文件，随数据库一起进入备份。设置页的"仓库完整性"扫描已覆盖位图 DDS 的双向检查：逐条 `pin_board_bitmaps` 记录校验 DDS 存在、路径归属（`<item-id>.dds`）、DDS/DX10/BC7 头、声明尺寸与记录一致、数据长度与 BC7 解码，并统计无记录的孤儿 DDS；文字与笔迹条目没有 DDS，不进入这项检查。`pin_board_bitmaps` 无摘要列，故不比对 SHA-256。孤儿 DDS 同时进入 `cleanup::scan_unreferenced` 的报告与确认清理流程。只报告不自动修复。

前端渲染器通过 revision 做保存冲突保护，纹理由 Rust 校验并按所需尺寸读取。前端分为 controller 与纯渲染器两层：`usePinBoardController.ts` 持有画板列表与选择、保存/导入/导出状态、错误状态，并注册 `preparePinBoardRuntimeChange` 使用的生命周期参与者；`PinBoardModule.tsx` 只负责视图、弹窗与局部交互，`PinBoardRenderer` 只处理 GPU、画板装载与绘制。导入/导出/文字的进度经 `CommandContext` 广播 `AppEvent.operationProgress`（`domain = pinBoard`），不再使用 `Channel`；`Channel` 只保留给需要传输大块载荷的通道。控制器统一使用共享 `useRequestEpoch` 做画板/作品切换的读取代次；不允许进代次的画板列表写回（新建、重命名、回收站、排序）在回填前比对作品 id，因此旧作品或旧画板的异步结果不会覆盖当前画板。设置契约 `PinBoardModuleSettings` 与其它边界类型一起放在 `types.ts`，控制器不再反向导入组件模块。

模块入口位于 Artwork 工作区的一个标签页，**保持挂载**：切换工作区视图只暂停全局键盘交互与在途纹理任务，不释放 GPU 资源；重新激活后从当前视口继续补载。该标签页沿用 Client 的 keep-alive 语义，非活跃时只切换可见性（`visibility`）而不是用 `display:none`，使画布始终保有布局尺寸，渲染器首次创建即可按最小包围框完成视图适配（否则会在零尺寸画布上初始化并写入退化会话，重进时图片过小且跳过适配）。

**渲染器与 GPU 设备在模块生命周期内只创建一次**：`PinBoardRenderer.create` 只做画布生命周期内的一次性初始化（适配器/设备/上下文/管线/采样器/`ResizeObserver`/主题观察器/事件监听），画板数据由 `loadBoard(view, session, stagePrevious)` 装载。切换画板与切换作品都只换数据、复用同一设备，且**装载是同步的**：先把旧画板的未保存改动导出成快照交给后台结算队列（`pendingSettle.ts`），再**释放旧画板的全部纹理**（切换即全释放，不跨画板保留）并装载新画板，同一 `boardId` 幂等；`stagePrevious=false` 用于旧画板已被删除或移入回收站、不能再次写库的场景；`unloadBoard` 用于当前作品已无画板时清空画面。`destroy()` 只用于模块真正卸载：仓库切换（`LibraryModule` 以仓库路径为 key 整块重建）、切到非作品节点或退出。这消除了旧实现「切换即创建/销毁渲染器与 WebGPU 设备」的 churn——该 churn 已确认会触发 WebView2 渲染进程冻结。

**切换不等仓库写入：旧画板的改动交给后台结算队列**。此前 `loadBoard` 要先以旧 `boardId` 完成 `save_pin_board` + `finalize_pin_board` 才装载新画板，切换因此被仓库写锁绑架：维护扫描、恢复、精简这类长任务持锁几十秒到几分钟时（实测一次仓库完整性扫描持锁 111 秒），交互写排队 10 秒后按 `repository_busy` 失败，界面停在新作品、画布停在旧画板。现在 `loadBoard` 只做同步的状态交接，写回交给 `pendingSettle.ts` 的串行 worker，因此切换本身不取写锁，后台任务再长也不影响切换。两条硬约定：

- **没有未保存改动就不产生快照**。`dirty` 为假时切换完全不碰仓库——切一次作品不该在数据层变成一次写操作。软删除条目的回收（`finalize_pin_board`）也不再挂在切换上，而是由队列在对应保存成功后按 `2 s / 8 s` 补做，全部失败只写日志（数据已落库，残留由下一次保存、退出结算或设置页清理扫描收走）。
- **同一画板只有一个写者**。渲染器再次装载该画板时用 `takeBoardSettle` 取回快照内容（`dirty` 保持为真、`savedStateKey` 清空），队列随即不再负责它；若取回时队列正在写同一份内容，那次写仍会完成，但不会覆盖后续编辑。`revision` 由共享账本 `resolveBoardRevision` / `recordBoardRevision` 统一给出——渲染器装载与保存都从账本取值，避免切换期间队列已推进 revision、渲染器还拿着旧值去撞「画板已被其他窗口修改」。切换时若该画板还有一次保存在飞行，队列会先等它落地（`stageBoardSettle` 的 `after`）再写，避免同样的 revision 冲突。

队列的可见性：失败分两类。可重试的（`retryable` 为真，含 `repository_busy` 与 IO 抖动）按 `0.5 s → 15 s` 指数退避**无限重试且不弹错误**，正常情况用户只会看到一条短暂的「正在后台保存 N 块画板的改动」（延迟 800 ms 才出现，避免瞬时完成时闪一下）；不可重试的（revision 冲突、仓库只读）停止自动重试、保留快照，并在素材板页头下方常驻一条「N 块画板的改动还没写进仓库：原因」+「重试」。快照只在内存里：进程被强杀会丢掉还没写回的改动，这是为「切换永不被写锁阻塞」刻意接受的取舍；退出与切仓库经 `flushPendingSettle` 在 5 秒预算内尽量写完。

**设备丢失走限流自动重建**：`device.lost` 后经 `makeGpu` 重建设备（与创建共用同一条初始化路径）并重新武装新设备的 `lost` 监听，随后按当前画板重载纹理；每个渲染器生命周期最多重建 2 次、带 600 ms × 次数退避，重建期间暂停绘制与纹理加载，超限或重建失败即保持挂起并只上报错误。

**创建失败走常驻说明，不进入瞬时状态栏**：环境不提供 WebGPU 适配器（`requestAdapter()` 返回 null）、适配器不可用或缺少 `texture-compression-bc` 时 `PinBoardRenderer.create` 直接拒绝，此时画布区显示一条**常驻**的「素材板不可用」说明并注明原始原因，编辑控件保持禁用，同时**不再显示「画板已锁定」**——渲染器为空时的锁定状态并非用户所为，显示它只会把排查引向错误方向。这条说明不能复用 4.5 秒自动清除的状态栏：那条链路清空后画板只剩空白与禁用按钮，用户会误判成卡死。素材板是本应用**唯一依赖 WebGPU** 的模块，缺少可用适配器的环境（未开启 3D 加速的虚拟机、部分远程桌面）其余功能不受影响；运行要求见 `README.md` 的「运行环境」，验收口径见 `docs/guides/release-policy.md` 的人工门槛。

工作区挂载：历史/发布/识别三个窗格以 `artworkId` 为 key 整块重置，**素材板窗格不带 key**，因此跨作品保留渲染器与设备；仓库切换/关闭时工作区整体卸载，画板状态随之丢弃，卸载路径执行 renderer 的保存/结算。

持久化只属于 Rust：SQLite（仓库 schema v5 起为多态条目表，v6 起含笔迹）保存画板、公共条目、按 kind 的载荷子表与 step 历史；位图实体存为 BC7 DDS `artworks/<artwork-id>/boards/<board-id>/<item-id>.dds`，文字与笔迹载荷只存数据库。不迁移 Lilith Client 的旧 `index.json` 画板库。

## 并发与锁

- 普通浏览（列表、加载、纹理读取、导出 PNG 到剪贴板）经 `OperationCoordinator::run_read`
  走共享读租约；各读命令附带标签（如 `read_pin_board_texture board=.. item=.. dim=..`），使
  `repository read took N ms` 慢读告警能归因到具体命令；
- 保存、粘贴、导入、画板增删改与回收站操作经 `run_repository_write` 走仓库 lease + 仓库操作锁；
  结算（`finalize_pin_board`）改走 `run_repository_write_shutdown`，以 Shutdown 优先级插入进程内
  写入闸门最前、等待上限 10 秒，前端在结算遇 `repository_busy` 时重试一次。`pin_board` 命令在
  `app/command_registry.rs` 直接注册，不经 `app/workflows.rs`，因此仍不持有 `BackupState` 运行锁；
- 灾备、scrub、仓库完整性操作持仓库操作锁期间，画板写入会被阻塞（读取仍可继续）。

## 存储布局

```text
<repository>/artworks/<artwork-id>/
  boards/<board-id>/<item-id>.dds    ← 位图条目实体（BC7）；文字与笔迹条目没有文件

SQLite:
  pin_boards        id, artwork_id, name, sort_order, now_step, max_step,
                    revision, deleted_at(回收站软删除), 时间戳
  pin_board_items   id, board_id, kind(0=位图, 1=文字, 2=笔迹), created_ms
  pin_board_bitmaps item_id, file_path, 逻辑宽高
  pin_board_texts   item_id, text, font_family, font_size, color, align,
                    measured_width, measured_height
  pin_board_strokes item_id, tool(0=pen 1=line 2=arrow 3=rect 4=ellipse),
                    color, stroke_width, 包围盒逻辑宽高, geometry(几何 BLOB)
  pin_board_history (board_id, item_id, step) → deleted, layer, sort_order,
                    transform_json(points/uv)
```

- `revision` 每次画板内容写库（`save_pin_board`/`finalize_pin_board`）后单调更新，用于保存冲突检测；`reorder_pin_boards` 只调整 `sort_order`，`rename_pin_board` 只更新 `name` 与 `updated_ms`，都不改 `revision`，因此重排或改名不会让已打开画板的下一次保存被误判为冲突；
- 笔迹是第三种条目（`kind = 2`）：只落数据库，不建纹理、不落实体文件，因此不进入 DDS 引用清单、清理、scrub、孤儿扫描、磁盘空间统计与系统剪贴板复制（系统剪贴板仍只认位图）；**画板内复制/粘贴支持三种条目**（载荷只记来源，见「命令面」）；
- 笔迹的 `layer` 固定为标注层 3，永远在所有图片与文字之上：`save_pin_board` 忽略前端传入的 `layer` 并强制写 3（防御性契约，配单测；同一份几何下只改 `layer` 不算改动、不产生新步骤），超出 0–3 的取值仍被拒绝，文字与图片照旧使用 0–2；
- 笔迹几何的 BLOB 布局、长度/点数校验与批量打包口径由 `stroke.rs` 与 `strokeGeometry.ts` 两侧各持一份，任何一侧改动都要同步另一侧与各自测试；单笔点数上限 4096，编码侧超出即拒绝，抽稀与重采样由 `strokeSampling.ts` 在编码前完成；形状（直线/箭头/矩形/椭圆）不带点数据，两端点由包围盒与方向位推出，退化包围盒（水平或垂直线）由前端按线宽膨胀后再存，读侧拒绝零尺寸；
- DDS 落盘（`persist_dds_file`）会先确保画板目录存在，仓库数据迁移后目录缺失时自动补建；
- 画板删除 = 软删除（`deleted_at`）；Artwork 进入项目回收站时其画板随之隐藏；Artwork 永久删除时 `pin_boards` 行随外键级联删除，DDS 目录随 `artworks/<artwork-id>` 目录一并进入清理队列；
- 画板回收站的永久删除/清空经 `pending_file_cleanup` 以 `repository_directory` 条目清理 `boards/<board-id>` 目录，失败保留并在下次启动重试；两者都经共享 `ConfirmDialog` 确认，其中「清空回收站」的最终动作由滑动确认控件承担，单块画板的永久删除沿用点击确认；
- 画板结算清除仍为删除状态的条目时，位图条目的 DDS 同样经 `pending_file_cleanup` 以 `repository_file` 条目（原因 `pin_board_finalize`）清理：事务内入队、提交成功后由命令层单遍重放删除。提交失败则入队随事务回滚，记录与 DDS 保持一致；删除失败条目留在队列可重试（`pin_board_finalize` 条目未落库 SHA-256，重放只做引用检查后删除），不阻断结算、不循环重试。文字与笔迹条目没有实体文件，结算只删除条目记录。重放的引用检查走中立契约：本模块的 `PinBoardReferenceInventory` 负责把 `pin_board_bitmaps` 记录映射成 `artworks/<artwork-id>/boards/<board-id>/<item-id>.dds`，cleanup 不再认识画板路径布局——记录删除前 DDS 视为被引用而保留，删除后才可清理；`file_path` 不是规范文件名的坏记录不参与引用，由完整性扫描报告；
- 无记录的孤儿 DDS（异常退出、手工复制或历史迁移遗留）由 `cleanup::scan_unreferenced` 扫描 `artworks/*/boards/*/` 发现，经设置页「空间」页的「文件清理」区确认后入队清理（该区同时列出待清理队列并支持单条/全部重试）；`cleanup::scrub_board_dds` 的完整性检查另按记录逐条校验 DDS 内容语义（缺失/损坏）并统计孤儿，只报告不修复。设置页「空间」页的队列与扫描入口见 `docs/modules/history-and-backup.md`。

## 渲染

两条路径，按「有没有纹理」划分，最终落在同一个 render pass 里：

- **位图与文字**：一个条目一张纹理、一个 quad，按 `layer` 再按 `order` 逐个绘制；
- **笔迹**：不建纹理，整板可见笔迹合并成一条三角形列表，**在图片之后用一次 indexed draw 画完**。笔迹固定占标注层，因此不需要与图片交错，也不需要在图片处切分批次。

笔迹的顶点带「世界位置 + 局部坐标 + 图元参数」：局部坐标以条目包围盒为界（`x ∈ [0, width]`、`y ∈ [0, height]`，原点在左上，与图片 UV 同一取向），构建时经条目四角的双线性映射落到世界空间，因此移动、旋转、缩放**不需要任何额外变换代码**；`uv` 被左右或上下镜像时同一份映射会让笔迹跟着镜像。片元着色器在局部空间算距离场：自由笔与直线是两端宽度线性插值的锥形胶囊，矩形是 `abs(sdBox) - 半线宽`，椭圆是「隐函数值 / 梯度长度」近似（`k0·(k0−1)/k1`，比早先按 `min(radii)` 缩放准确得多，扁椭圆不会在长轴两端变粗），箭头是一段止于三角底边的杆加一个三角形；随后按视口 uniform 里的「设备像素 / 世界单位」做 1 px 羽化，缩放 10%–800% 边缘都清晰。

**每个图元的四边形必须盖住墨迹，不只是盖住羽化余量**。距离场以中心线/路径为基准，墨迹在两侧各占半个线宽，所以四边形要按「半个线宽 + 一个设备像素」外扩（`rectPrimitive` / `ellipsePrimitive` 传的就是这个值）。只按羽化余量外扩会把外侧半个线宽整条裁掉：矩形拖拽时预览是满宽、落地后瞬间只剩一条细边，椭圆则被自己的方框切掉左右两端——两处都曾是这个原因。椭圆额外留 `ELLIPSE_AA_MARGIN`（1.6 倍半线宽）的余量，因为它的距离场是近似值：长短轴差二十倍以内、线宽明显小于短半径的椭圆都盖得住；再极端的细椭圆仍会被切掉一点，那是近似本身的局限，不是外扩量不够。

**自由笔的相邻段首尾相接，不叠圆头**。每段各自带圆头时，两段的重叠区会把 1 px 羽化混合两次，而 src-over 混合在两条羽化边重叠处的结果比真实并集更实（0.5 + 0.5×0.5 = 0.75 而不是 0.5）：整条笔迹于是沿采样间隔出现一串亮点，细线缩小时看起来就像虚线。现在每个采样点按两侧法线的角平分线算一对「斜接」顶点（斜接长度 `r / cos(θ/2)`，夹到 `MITRE_LIMIT = 1.5` 倍半径），相邻段共用同一对顶点，边缘因此只被算一次。采样管道保留 75° 以上的尖角（`splitAtCorners` 只拆插值、不拆笔），75° 转角只需要 1.26r；更尖的转角由 1.5r 上限退化成斜切，宁可把外侧尖角切平一点，也不让斜接顶点拉出一根长刺。只有整笔的首尾点沿切线外扩一个半径，让圆头完整落在四边形里。

包围盒是**墨迹外框**：矩形与椭圆的路径从四边各内缩半个线宽，直线与箭头的两端点同样内缩半个线宽，方向位（0 左上 / 1 右上 / 2 右下 / 3 左下）决定起点落在哪个角。写入侧必须按线宽把包围盒向外膨胀，否则水平或垂直直线的退化包围盒会归一化除零（见归档计划的「风险 4」）。自由笔的点按压感收细（`0.15 + 0.85 × pressure`）。**是否带压感按整笔判定**：写入侧只在「指针是笔且确实收到过非零压感」时置位；整笔带压感时，笔迹内部的 `pressure = 0` 表示这一下几乎没使劲，按最细一档画，而不是回退成满宽。整笔无压感（鼠标、触摸或压感恒为 0 的驱动）时按固定线宽画。采样、光滑与两端 taper 在写入前的 `strokeSampling.ts` 完成，读侧只消费点序列。

低缩放下按距离抽稀：相邻点的距离不足一个设备像素时合并，首尾点始终保留，因此一条 300 点的笔画缩到 10% 会收成十来个点而不会断裂。抽稀的阈值按世界单位给出、距离在条目的局部坐标系里度量：条目显示尺寸与包围盒不一致时只会多留点，不会漏点。缓冲在「可见条目集合、缩放或几何版本」变化时重建，并记下构建时使用的收集框（视口四周各扩 0.5 倍宽高）：视口走出该框时即使可见集合没变也重建一次，否则逐段裁剪留下的空缺会在平移后露出来；框内平移不重建，拖动笔迹本身会重建。逐段裁剪在 `buildStrokeBatch` 内按世界四边形与收集框是否相交判断，完全落在框外的图元不写顶点。设备丢失时缓冲随纹理一起丢弃，由 `recoverGpu` 之后的 `refreshViewport` 按当前画板重建。

**笔迹必须排除的既有纹理路径**（漏掉会出「红色失败占位框」或显存空转）：`textureLoadCandidates`、`updatePlaceholderOverlay`、`requestedDimension`、`estimatedResidentBytes`。淘汰只遍历两张纹理表，笔迹本来就不在其中，因此 `evictTextures` 不需要改动。选中描边走独立的 line-strip 缓冲（每笔 5 个顶点、按槽位连续排布），与位图的包围框描边同一套颜色与线宽。

几何读取与画板装载解耦：`loadBoard` 保持同步，装载后若画板含笔迹条目才异步调用 `read_pin_board_strokes`，回来后重建缓冲并补画，因此切换画板不会为几 KB 几何多等一次 IPC。新建笔迹后（`applyMutationResult`）同样重读一次整板几何——几何不在条目 DTO 里。

笔迹能被选中，但单条导出与系统剪贴板复制只认位图：`interactionState.exportableCount` 只数位图，只选中文字或笔迹时「导出图片」「复制图片到剪贴板」按钮与右键项一起置灰，不再打开目录选择器后写 0 个文件；导出命令也只收到位图 id（`exportableImageIds`）。文字与笔迹没有单条导出入口，统一由**整画布导出**覆盖（见「整画布导出」）。

## 绘制

标注工具条（`.pin-board-drawbar`）**浮在画布内、靠下居中**，不占固定行：七个工具（选择、画笔、
橡皮、直线、箭头、矩形、椭圆）+ 取色器 + 大小滑条与数值输入。工具状态归渲染器所有（与 `locked` 同一类），
通过 `interactionState.tool` 广播给界面；**选择工具就是交互模式**——`select` 走原有的选中/框选/变换，
绘制与橡皮直接独占指针，没有额外的模式开关。取色器与大小是界面的状态，经 `renderer.setStrokeStyle`
推给渲染器，预览与落库共用渲染器里那一份值。滑条与数值框写同一份线宽状态：滑条拖动时数值框实时
跟随，数值框只在失焦或回车时收敛，输入过程中允许暂时不合法。工具条只在有画板且渲染器可用时出现，
全屏下同样保留；显隐只由快捷键 `T` 切换——工具条收起后自身不可见，条上与主工具栏都不放宽高按钮，
避免「隐藏后只能靠快捷键找回来」的不对称入口。

界面上这个值叫**「大小」**而不是「线宽」：它同时是画笔的线宽与橡皮的直径。内部标识符仍是
`strokeWidth`（它描述的就是笔迹线宽这一物理量），切换工具不记忆独立数值——橡皮直径直接取当前
「大小」，环形光标因此改一下就能看到。

**线宽上限 500，滑条走指数映射**（`MIN/MAX_STROKE_WIDTH`、`strokeWidthFromSlider` /
`strokeWidthToSlider`，刻度 0–`STROKE_WIDTH_SLIDER_STEPS`）。上限比前端几何契约与原生端
`MAX_STROKE_WIDTH`（1000）保守一档，不必改 schema。滑条位置与线宽之间是指数关系，行程再按
`t^0.75` 往细线端挪一点：细线端每前进 10% 线宽乘约 1.9 倍，粗线端只乘约 1.6 倍（纯指数下整条
滑条都是 1.86 倍，右半段因此一拖就窜）。1–20 这段最常调，占到约 38% 的行程，200 以上那一段
占最后两成。线性滑条会把九成行程分给一辈子用不到的粗线，这是改用非线性的原因；数值框仍可手输
精确整数。

**画笔工具用笔尖光标**（画布上的 `.tool-pen`，热点对准笔尖），**橡皮用环形光标**
（`.tool-eraser` + 画布外层的 `.pin-board-eraser-ring`），其余工具保持十字：类名由
`emitState` 按 `tool` 统一切换，而 `setTool` 结尾就发一次状态，所以选了工具光标立刻变；CSS 里
`.pin-board-canvas.drawing:not(.tool-pen)` 才回到十字，因此落笔过程中笔尖光标不会闪成十字，
而 `locked` / `dragging` 这类拖拽态仍按先后顺序覆盖它。

环形光标是一个 `pointer-events: none` 的 DOM 空心圆，直径按「大小 ÷ 世界单位每 CSS 像素」换算
（视觉最小值 4 px）：它表示的是世界里的擦头，缩放变化后屏幕上的圆也必须跟着变。位置在每次
`pointermove` 更新，`pointerleave`、切工具、锁定、设备不可用与卸载时隐藏；`destroy` 时移除节点。

取色浮层挂到 `document.body`（`PinBoardColorPicker`），按触发按钮的视口矩形选择向上或向下展开并
收敛最大高度：工具条为窄窗口保留横向滚动，`overflow` 会裁掉内联的绝对定位浮层。浮层的 `z-index`
高于文字对话框，全屏画布下也不会被盖住。

**状态机与指针分支**：`select` 沿用原有的选中/框选/变换；绘制工具与橡皮下 `pointerdown` 直接独占该次
拖拽（`dragMode = "draw"` / `"erase"`），不触发选中与框选，中键平移不受影响。切到这两类工具时会清空选中、
`dragBefore` 与 `marqueeBaseIds`——拖拽中不该继续显示变换手柄，也不该把上一轮的拖拽快照带进来。
`isStrokeTool` 只表示「会产生几何」（五种绘制工具），`isDrawingTool` 才表示「独占指针」——橡皮属于后者
而不属于前者，否则绘制分支会去编码一个不存在的草稿。**绘制工具下新建的条目也不会自动选中**
（`applyMutationResult` 只在 `tool === "select"` 时加入选中）：工具模式的指针只走绘制/擦除分支，
包围框既拖不动、又会挡住下一笔。锁定时工具按钮禁用，`toggleLock` 同时把工具退回 `select`，
避免停在「笔」或「橡皮」上让人以为还能画。

**实时预览层**：绘制过程中只往一个 DOM 2D canvas（`.pin-board-draw-overlay`）上重绘当前草稿，**不在每次
`pointermove` 重建 GPU 缓冲**。预览把画布变换直接设成「世界坐标 → 设备像素」，因此线宽、形状尺寸与
落库后的渲染天然一致，不必两处各写一份换算；自由笔在数位笔下按压感画成变宽墨迹（半径与着色器共用
`strokePointRadius`），鼠标仍画等宽折线；直线/箭头画线段（杆止于三角底边）加三角，矩形与椭圆用
`strokeRect` / `ellipse`。预览与落库是否带压感用同一个判定（指针是笔且收到过非零压感），避免
「预览细、落库粗」。视口变化（缩放、窗口尺寸）时预览跟着重算。

**Shift 约束**：自由笔约束成从起点出发的直线；矩形约束为正方形、椭圆约束为圆（边长取两轴拖拽量的
较大值，方向沿用拖拽方向）；直线与箭头吸附到 45° 的整数倍，并把拖拽量投影到吸附后的方向上，终点
仍落在光标那条射线上。

**采样**：`pointermove` 一次事件会把 `getCoalescedEvents()` 里的全部中间点都喂给草稿（不可用或返回空时
退回事件本身），因此 Chromium 把事件合并到约 60 Hz 也不会丢点；`pointerup` 再补最后一个点，快速收笔
不会少画最后几个像素。草稿只保留原始采样（世界坐标 + 压感），不做抽稀——预览要画的就是它们。

**落库**：`pointerup` 时才把草稿编码成包围盒 + 几何 BLOB（`strokeDrawing.resolveStrokeDraft`），经
`onStrokeCommit` 交给控制器：串行队列 → `save_pin_board` 落地未保存的变换 → `create_pin_board_stroke`
→ `applyMutationResult` → 重读整板几何 → 预览才撤掉。中间不立刻清预览，否则每个往返都会闪一下空白；
提交失败或画板切走时也会清掉，不会在画布上留一条不存在的笔迹。串行化是必需的：创建命令带 revision
校验，两笔并发落库会拿着同一个 revision。**创建命令返回的 revision 必须同时写进共享账本**
（`applyMutationResult` 里的 `recordBoardRevision`）：保存时 `resolveBoardRevision` 以账本为准，只更新
渲染器自己的 `revision` 会让账本停在上一笔保存的值，之后每次保存都拿旧值撞「画板已被其他窗口修改」，
而提交前的保存失败又会让后续每一笔都直接丢弃。装载画板时同样把取到的 revision 记进账本，避免账本里的
旧值压过刚读到的仓库事实。拖拽距离不足 3 个 CSS 像素按误点处理（不产生条目），自由笔
单点同样按取消处理——单点画不出线段，留下来只会是一个看不见的条目。`pointercancel`（系统收回指针）
按取消处理而不是落库。

**快捷键**：`V` 选择、`P` 画笔、`E` 橡皮、`L` 直线、`A` 箭头、`R` 矩形、`O` 椭圆，`T` 收起/展开标注工具条；
都只在没有 `Ctrl`/`Cmd`/`Alt`/`Shift` 修饰键、且焦点不在输入框内时生效（`shortcutCanHandle`），
与 `Ctrl+A`/`Ctrl+R` 等组合键不冲突。

**采样管道**（`strokeSampling.normalisePenSamples`）：自由笔在编码前依次做去重 → RDP 抽稀 → 在尖角
（转角 ≥ 75°）拆段 → 向心 Catmull-Rom 转三次贝塞尔 → 按弧长等距重采样 → 压感滑动平均 → 两端 taper
（笔尖与收笔按余弦斜坡收到一半宽，太短的笔迹不做）。RDP 容差取 1 CSS 像素、重采样步长取 2 CSS 像素，
再与线宽的一个小比例取较大值，并**按绘制时的缩放换算成世界单位**——画的时候多细，存下来的点密度就
多细，放大后不会看到折线。点数超过 4096 时先按长度放宽步长、最后再均匀抽稀，写入侧因此不会再因点数
被拒绝。

**写入侧的包围盒口径**：与「渲染」一节的读侧一致——自由笔取「点中心极值 ± 半径」，形状取「两端点外扩
半个线宽」，矩形与椭圆因此从四边各内缩半个线宽回到用户拖拽的框；形状的方向位按局部坐标计（局部 y
向下），由起点落在哪个角推出。

## 橡皮擦

**只擦笔迹**，位图与文字不参与。按下即判定一次（环形光标给出的是「这里能点到什么」的预期，单击
笔迹毫无反应会像失灵），继续拖拽则在 `pointermove` 里增量擦；按下后没碰到墨迹也照样进入拖拽状态，
因为继续拖可能才碰到。

**按扫过的轨迹判，而不是只判当前点**（`strokeHitBySweep`）：每次 `pointermove` 拿「上一帧位置 →
这一帧位置」这一段，判墨迹折线到这条线段的距离 ≤ 「墨迹半径 + 擦头半径」。原因是浏览器把
`pointermove` 合并到约 60–120 Hz，快速擦动时相邻两帧可能隔几十个像素——只测采样点会让细笔迹正好
落在两次采样之间，整条都擦不到，表现就是「反复擦没反应、点一下反而擦掉」。单点（按下那一刻）退化
为圆形判定。

**命中在世界空间算**（`strokeHit.ts`）：条目几何展开成世界折线 + 每点墨迹半径，擦头圆到折线的距离
≤ 「墨迹半径 + 擦头半径」即命中。选世界空间而不是条目局部空间，是因为条目可以旋转、镜像（`uv` 翻转）
与非等比缩放——局部空间里的圆在世界里是椭圆，逆变换回来只会引入近似；而自由笔的归一化点、形状的
两端点本来就要经同一份 `mapLocalPoint` 落到世界。覆盖口径与渲染一致：自由笔逐点带压感半径，形状统一
用半个线宽；箭头除杆外还包含头部三角（闭合折线），否则从侧面擦箭头会擦不掉；矩形与椭圆按描边算，
框内是空的。

**预筛与缓存**：先按「条目包围盒外扩擦头半径」与「这一段位移的包围盒」求交，跳过不可能命中的条目
（热路径上最省的一次判断），命中才解析几何；世界折线按条目 id 缓存，签名由「几何版本 + 四角 + `uv`」
组成，变换或几何版本变化即失效。同一轮里已擦掉的条目不再重复处理。

**撤销口径**：一次拖拽一条撤销记录。按下时对**全部可见笔迹**取快照，`pointerup` 时以「擦掉的那几条」
为 after 推入历史；什么都没擦到就不推历史、也不标 dirty。`pointercancel` 与 `pointerup` 走同一条提交
路径——擦掉的内容不还原，否则用户会看到「擦掉的东西又回来了」（绘制的中断才按取消处理）。

**可见性**：只擦未删除、`available` 且所在图层可见的笔迹；隐藏标注层时连拖拽都不进入。擦除会触发
`afterLiveChange`（脏标记 + 重建笔迹缓冲 + 排程自动保存），与拖拽移动图片同一类提交。

## 点选与框选的命中

点选与框选**复用橡皮擦那套墨迹几何**（`strokeHit.ts`），只是「放宽多少」的来源不同：橡皮擦用擦头
半径，选择用固定的最小容差（`STROKE_HIT_TOLERANCE_CSS_PIXELS = 3`，按当前缩放换算成世界单位，
因此屏幕上恒定）。容差是必要的——1–3 px 的细线只按半个线宽判，光标偏一个像素就点不中。

- 笔迹的点选判「光标到折线的距离 ≤ 墨迹半径 + 容差」（`strokeHitByCircle`）；框选判「折线与框选
  矩形是否相交」（`strokeIntersectsBounds`，每段按两端半径的较大值 + 容差外扩）。于是**框住椭圆或
  矩形的内部、却没碰到描边时不选中**，点中空心处同样不选中——这就是「按绘图区域而不是包围框」。
- 位图与文字仍按四角框：位图不读回纹理就无从知道 alpha，文字框本来就贴合字形墨迹。文字的行间空白
  因此仍算命中，不值得为它做字形级判定。
- 框选是每个 `pointermove` 都要跑的热路径，所以两次便宜判断挡在分段求交前：外框（外扩容差）与框选
  矩形不相交 → 直接否；框选矩形完全罩住外框 → 直接是（「一大片整体框住」这个最常见操作因此不退化）。
- 笔迹几何还没读回来（刚打开画板）时退回四角框，宁可选中也不要「点了没反应」。

`selection.marqueeSelection` 只接受一个可选的命中谓词：默认仍是四角框，渲染器传入上述按条目类型
分派的判定（`renderer.itemIntersectsMarquee`）。这样删除/可用性过滤只有一处，纯函数也不必知道笔迹几何。

## 图层可见性

四个开关：底层 / 中层 / 顶层 / 标注层，各自独立。文字跟随它所在的 0–2 层一起显示或隐藏，不需要单独
一档；标注层只装笔迹。

**纯视图状态**：不进 schema、不写库、不标记 dirty、不进撤销栈——「藏起一层看一眼底图」不该变成一次
仓库写操作。状态放在 `session.ts` 的 `PinBoardViewSession.visibleLayers`（下标即 `layer`），随画板会话
在进程内恢复：切走再切回保持，重启应用后回到全部显示。类型、默认值与归一化在 `layers.ts`：
`normalizeLayerVisibility` 缺项按「显示」补齐，`isLayerVisible` 对未知 layer 也按显示处理——异常数据
不该把一层内容永久藏起来。

**必须一起接的五处判断**，少接一处就会出现「看不见但能选中」：`refreshViewport` 的 `visibleImages`、
框选的输入集合（`marqueeSelection` 收的是完整 `images`，这里先按可见层过滤）、`selectAll`、
`contentBounds`、`selectedImages`。最后两处决定「重置视图」与删除/导出/变换只看可见内容：隐藏标注层
后重置视图不会缩放到一片空白，隐藏层里的条目也不会被删除或导出。

隐藏某层时该层里正被选中的条目一并退出选中（`hiddenSelectionIds`），恢复显示不会把它们重新选上。

**创建与绘制不落进隐藏层**：选绘制或擦除工具时自动打开标注层（藏着还让人画/擦，画完什么也看不见）；文字、
粘贴与导入的新条目如果落进隐藏层，也会把那一层打开——否则「添加成功」看起来像什么都没发生。

**UI**：画布左上角一块悬浮的图层面板，收起后只剩一个图层按钮。展开时是四行开关，标注层排最上；
每行一个眼睛图标、层色块、层名与**该层未删除条目数**，隐藏的图层整行变淡。数字来自
`interactionState.layerCounts`（下标即 layer，长度 4），**隐藏层里的条目照样计入**——它表示「这一层里
有多少东西」，不是「现在看得见多少」，否则开关一次图层数字就跳一下。标注层不显示数字（那一层只有
笔迹，数字既不是用户关心的、也容易和层名混读），但数据仍然给全。数字带 `aria-hidden`，行按钮另有
`aria-label`，可访问名不会变成「顶层 12」。任一图层被隐藏时，收起状态的按钮同样高亮。
面板与标注工具条一样浮在画布内、不占主工具栏——主工具栏已有二十来个按钮，再排四个会被横向滚动
藏掉；全屏时主工具栏隐藏，面板仍然可用。面板不做快捷键，展开与收起只由面板自身的按钮控制。

**只在两种情况下置灰**：渲染器不可用，与整画布导出期间。画板锁定**不**禁用图层开关——锁定挡的是
改模型的操作，而显隐不写库、不标 dirty、不进撤销栈，`renderer.setLayerVisible` 也只检查 `loaded`；
「锁住画面、藏掉标注层看底图」正是锁定状态下的常用动作。禁用条件的纯函数是
`PinBoardModule.tsx` 的 `pinBoardLayersPanelDisabled`（只收 `hasRenderer` 与 `exporting` 两项），
不要把它并回按钮组共用的 `editingBlocked`（那个还含 `locked`）。

**笔迹仍固定标注层**：右键菜单的图层项在选中含笔迹时置灰，提示「笔迹固定在标注层」。混选（图片 +
笔迹）整组拒绝而不是「只改图片」：半执行的图层切换没有可见反馈，用户会以为笔迹也跟着换了层。
`arrangeableCount` 只数位图，笔迹天然不参与阵列排序；`bringToFront` 只把笔迹在**笔迹内部**提前，
不动它与图片/文字的先后关系——跨层先后由 `layer` 决定，把笔迹提到整板最前只会改写每个条目的
`sort_order`，一次点击就脏整块画板。

## 整画布导出

把整块画板按**可见内容**合成一张透明 PNG：所有未删除、`available` 且所在图层可见的条目，按内容
外框裁剪，边距默认 10 像素、可调 0–64。文字与笔迹因此也有了交付级出口——它们的单条导出已删除，
统一并入这里。缺失 DDS 的位图画不出来，也不参与外框计算，否则导出图上会出现一块谁也没见过的空白。
空白处的右键菜单也有「导出画布」，与工具栏那个按钮打开同一个对话框。

**倍率与上限**：1 世界单位 = 1 像素记作 1x。倍率**可手动填**（0.01–8），默认值是「1x 与塞进
建议上限取小」（内容 45000 宽、上限 20000 → 0.44），填过之后以填的为准。建议上限只按最长边、
取素材板设置的「纹理缓存等级」（低 10000 / 中 20000 / 高 30000 像素），超过它**只提示不拦截**
——对话框显示警告、主按钮改成「仍要导出」，导出照常进行。真正的硬上限是边长 65535 与总像素
10 亿（与原生侧 `MAX_OUTPUT_PIXELS` 同口径），只用来挡住荒谬输入，撞上时倍率被收敛且输入框回写
收敛后的值；收敛按**最终整数尺寸**算——取整可能把乘积顶过像素上限（边长 √10 亿见方的内容两边
各向上取整就多出十几万像素），此时从长边扣掉多出来的像素，返回的倍率也改成该尺寸对应的值，
因此「前端算得出来、原生拒绝」不会发生，块→世界的映射与「输出 W×H」也严格一致。倍率、输出
尺寸、行带与分块布局全在 `exportPolicy.ts` 的纯函数里：对话框的「输出尺寸」与真正写出的 PNG
共用同一份计算，两处不可能算出不同尺寸。**不做耗时估算**——机器差异太大，一个不准的数字只会
误导人，进度条本身已经回答了「还要多久」。

**对话框的三个数字互相咬合**：倍率是唯一的事实来源，输出宽度是它的另一种写法（改哪个都把另一个
算回来），边距只改画布范围（倍率不动、宽度随之变化）。文件名默认取画板名、可改，原生侧仍会清掉
非法字符并在重名时追加序号。

**离屏渲染通道**：渲染器平时只画 swap chain，导出走一条并行通道——独立的导出 uniform（逐块
写入，与屏幕的 `viewportBuffer` 分开）、独立的渲染目标纹理（`rgba8unorm`，
`RENDER_ATTACHMENT | COPY_SRC`），以及**目标格式为 `rgba8unorm` 的管线副本**：着色器与绑定布局
与屏幕完全相同，只有 `format` 不同，`createBoardPipelines` 一份代码按目标格式建两套。选
`rgba8unorm` 而不是画布格式是为了回读后能直接按 RGBA 编 PNG，省一次通道交换；清屏值全透明，
混合仍是标准 src-over。导出通道**不画**选中描边、纹理占位框、框选矩形与绘制预览。笔迹缓冲按
整个导出区域单独构建一次（`buildStrokeBatch` 的 `cullBounds` 传导出区域），屏幕那份
（`strokeVertexBuffer` / `strokeIndexCount`）一个字段都不动。

**纹理分辨率**：位图纹理平时按屏幕缩放请求，2x/4x 导出沿用屏幕分辨率会明显发糊，因此按
「显示尺寸 × 导出倍率」重新请求，只针对当前块涉及的条目，并复用现有的读取、预算与淘汰机制。
两条硬约定：

- 单张就要吃掉四分之一显存预算时不升级——预算里塞不下几张，反复淘汰比降一点保真度更糟，
  此时退回现有纹理（屏幕分辨率或缩略图）；
- **当前块涉及的条目在淘汰时受保护**（`exportProtectedIds`）。导出区域的条目往往不在屏幕
  视口内，而淘汰优先挑「不可见」的，不保护就会把这一块刚准备好的纹理淘汰掉，那块直接变空白。

加载失败只记日志、保留现有纹理：不为一张位图的高清版本让整次导出失败。

**分块与回读**：块宽 `min(8192, 剩余宽度)`，行带高度
`clamp(floor(32 MiB / (输出宽 × 4)), 128, 2048)`（8000 宽 → 1048，20000 → 419，30000 → 279）。
按「行带优先、行内从左到右」推进：每块设一次视口、渲染到同一张导出纹理、`copyTextureToBuffer`
（`bytesPerRow` 按 256 对齐）→ `mapAsync` → 去掉行尾 padding → 交给原生端。常驻内存因此只有
一个行带，与输出尺寸无关。

**原生流式拼装**（`canvas_export.rs`）：`begin` 在输出目录建临时文件并写 PNG 头，`write` 逐块收
原始 RGBA（坐标与尺寸走 header、像素走 `InvokeBody::Raw`，避免几十 MB 的 JSON 数字数组），
一条行带拼满立刻写盘，`finish` 校验写满、写 IEND、`sync_all` 并原子改名，`cancel` 丢弃会话与
临时文件。会话单并发，块的到达顺序与尺寸被严格校验（越界、乱序、行带不完整一律报错）。
**不取仓库写租约、不取仓库操作锁**：只写用户选的输出目录，因此导出期间后台的完整性扫描、
自动备份与清理照常运行，不会互相把对方挡成 `repository_busy`。临时文件放在输出目录内（同卷
改名才是原子操作），强杀残留按前缀在下次 `begin` 时清掉。文件名取画板名，清掉非法字符、重名
追加 `-2` / `-3`，绝不覆盖已有文件。

**进度、取消与锁定**：进度由前端自己算（已发送块 / 总块数），走 `.pin-board-transfer` 那条共用
状态条，取消按钮与进度条同排；不逐块走 `AppEvent.operationProgress`，避免每块一次事件。
导出期间渲染器置 `exporting`（`interactionState.exporting`）：指针、滚轮、快捷键与工具切换一律
不响应，工具栏、图层面板、画板列表、粘贴/导入/导出入口一起禁用（锁定不在其中：图层面板锁定时
仍可用，见「图层可见性」）；离开工作区、切画板、切作品或卸载都会在下一块之前中止并调用 `cancel`。
导出的是渲染器内存里的当前状态，**不落库**，因此整段流程不产生任何仓库写操作（挂起的自动保存也
推到导出结束之后）。

**共用的传输进度条与取消**（`PinBoardTransferProgress`）：导入图片、导出图片与整画布导出共用
一条进度条（`.pin-board-transfer`，一行放下「在做什么 / 进度 / 百分比 / 取消」），可取消的传输
才渲染取消按钮。取消分两条链路：

- **整画布导出**：渲染器在下一块之前检查 `transferCancelRef`，命中就中止并让原生端丢弃临时文件；
- **导入/导出图片**：原生侧的长循环，取消信号在 `pin_board::transfer::PinBoardTransferCancel`
  （一个原子布尔，传输开始时复位），循环在**条目边界**检查。导入取消整笔回滚、已写出的 DDS 由
  `CreatedFiles` 一并删除，画板上不会留下半批条目；导出取消保留已写出的完整 PNG（部分导出），
  状态栏报「已取消导出」。拖入文件的导入是前端逐张落库，取消即不再发起下一张，已落库的保留。

全屏下工具栏收起但进度条保留——它是导出期间唯一的取消入口。

## 命令面

- 画板管理（`api.ts` → Tauri 命令）：
  - `list_pin_boards(artworkId)`、`list_pin_board_trash()`（全局列表，含原属作品标题）
  - `create_pin_board`、`rename_pin_board`、`reorder_pin_boards(artworkId, boardIds)`（侧栏拖放排序）、`trash_pin_board`、`restore_pin_board`（恢复回原 Artwork）、`delete_pin_board_permanently`、`empty_pin_board_trash`

画板内容：

- `load_pin_board`、`save_pin_board`（`items` 为纯变换 DTO）、`finalize_pin_board`
- `paste_pin_board_items`（画板内粘贴）、`import_pin_board_images`（文件路径）、`import_pin_board_clipboard_image`（剪贴板位图素材，也承接拖入导入的字节）——三者统一写入归一化 BC7 DDS，导入/导出进度经 `CommandContext` 广播 `AppEvent.operationProgress` 回传（不再使用 `Channel`，只保留给需要传输大块载荷的通道）
- `create_pin_board_text`（文本、字号、颜色、对齐、前端度量宽高与中心点）——文字条目只落数据库，不生成图片；创建后 0.3 不支持改字/改色/改字号
- `create_pin_board_stroke`（工具、颜色、线宽、包围盒、几何 BLOB、中心点与 revision）——原生端按读侧口径校验几何与包围盒后才落库，图层不由调用方决定（强制写标注层），几何走普通参数通道：`Uint8Array` 由 IPC 的 JSON 序列化还原成数字数组并落成 `Vec<u8>`，单笔 4096 点约 75 KB，不值得为此另开原始载荷通道
- `read_pin_board_strokes`（整板笔迹几何的二进制载荷，布局见 `stroke::encode_batch`：`u32 条目数` + 每条目 `itemId / tool / color / strokeWidth / 宽高 / geometryLen / bytes`）——前端一次解析成 `Map<itemId, StrokeGeometry>`，不经 JSON；含已删除但尚未结算的条目，可见性以 `load_pin_board` 的 `deleted` 为准
- `export_pin_board_images`（位图条目解码为 PNG 到用户选择目录）、`read_pin_board_image_png`（系统剪贴板复制，仅位图）、`read_pin_board_texture`（位图读取 DDS；文字与笔迹返回「没有 DDS」信号，由前端自行绘制）
- `read_pin_board_clipboard_paths`（Windows `CF_HDROP`）
- `cancel_pin_board_transfer()`：导入/导出图片的取消信号（`PinBoardTransferCancel`，进程级单并发），
  原生循环在条目边界检查；整画布导出不走它（那条例程由前端逐块推进）
- 整画布导出的一组命令共用一个单并发会话（`PinBoardCanvasExportState`）：
  `begin_pin_board_canvas_export(outputDirectory, fileName, width, height)`、
  `write_pin_board_canvas_export_tile(headers: x/y/width/height, body: RGBA)`、
  `finish_pin_board_canvas_export()`、`cancel_pin_board_canvas_export()`。像素走原始请求体
  （`src/shared/tauri.ts` 的 `invokeCommandWithBody`），坐标与尺寸走 header；**不取仓库锁**，
  口径见「整画布导出」

**画板内复制/粘贴**（`copySelection` → `paste_pin_board_items`）：

- 复制载荷只记来源：`PinBoardClipboardItem { kind, sourceBoardId, sourceItemId }`。尺寸、变换与载荷内容
  一律由原生端读源条目的**当前步骤**现算——前端带尺寸时那份值可能来自尚未落库的快照，与仓库里的
  记录不一致。
- 三类条目（位图 / 文字 / 笔迹）走**一条命令、一次事务、一次 revision**：拆成多条命令时，第二条失败
  会在画板上留下半份副本，混合选择必须原子。位图 DDS 复制、文字载荷与笔迹几何各自分派，位图才预建
  `pin_board_bitmaps` 占位行（`begin_item_mutation` 因此按 kind 数组而不是单一 kind）。
- **落位保持整组相对位置**：整组外框中心对到放置点，各条目之间的相对位置与复制时一致。此前位图按
  导入的阵列口径围绕放置点重排，多选粘贴会打散用户摆好的对齐关系；混合粘贴更是会错位。位图粘贴的
  手感因此与旧行为不同（属于已验收行为变更，见 `CHANGELOG.md`）。
- 图层沿用源条目（笔迹经 `effective_layer` 强制回 3）。源画板在回收站、源条目已删除、kind 与复制记录
  不一致、几何无效、像素超限、数量超限都会被拒，且**整组拒绝**。
- 系统剪贴板复制（`read_pin_board_image_png`）仍只认位图：文字与笔迹没有可贴到外部程序的载荷。
- 工具栏与右键的文案相应从「复制/粘贴画板图片」改为「复制/粘贴画板条目」——操作对象已经是三类
  条目，旧文案会让人以为文字与笔迹仍然贴不进来。

**仓库外路径的两道闸门**与认证模块同一口径，各管一件事：

- `import_pin_board_images` / `export_pin_board_images` 在命令层用
  `path_scope::ensure_authorized` 要求每条源图路径与导出目录都已在 Tauri 文件系统 scope
  中（原生文件选择器会自动写入）。scope 属于 UI 关注点，检查实现放在
  `src-tauri/src/path_scope.rs`，认证与素材板共用，领域模块之间不互相导入；
- `repository::import_images` / `export_images` 在领域层用
  `storage::ensure_outside_repository` 拒绝仓库内部的源文件与导出目录——GUI 与无头入口
  都会经过本函数，因此这一道对两条链路同时生效。

「复制文件后粘贴」仍可用：`read_pin_board_clipboard_paths` 由本命令自己从系统剪贴板读出
路径，并把确实存在的文件加入 scope，随后仍走同一条授权检查——路径不是渲染进程传进来的
值，所以这不构成绕过。粘贴**纯文本路径**不再导入（那种路径没有任何授权来源，Rust 层会
以「未由文件选择器授权」拒绝），需要路径的入口只剩文件选择器与剪贴板文件；拖入图片走的
是字节链路（`import_pin_board_clipboard_image`），不涉及路径。

## 领域行为（沿用 Client 已验证实现）

交互层（renderer、几何、纹理策略、会话、快捷键、画布交互）原样迁移，未重写。要点：

- 纹理两级缓存与淘汰策略、8192 纹理上限契约、BC7 解码预览见 `texturePolicy.ts` 与 `dds.rs`；缓存预算由设置的 `textureCacheLevel` 决定（Rust 结果缓存低 64 / 中 128 / 高 256 MiB，叠加前端 GPU 常驻缓存后总量约 256 / 512 / 1024 MiB，设置页按总量标注，与 Client 一致）；
- 图片状态沿用 step 模型：新增图片先有 step 0 的删除态默认节点，添加/变换/删除作为新步骤写入；普通保存追加当前历史节点并作废 redo，`finalize_pin_board` 截断未来步骤、清除仍为删除状态的图片记录（对应 DDS 的删除走 `pending_file_cleanup` 提交后重放，见上节）；
- 编辑自动保存：设置页「自动保存」开关（默认关闭）开启后，模型变化（拖放结束、缩放、旋转、图层/顺序调整、删除、撤销/重做）后静默 1.5 秒即自动 `save_pin_board`，期间再次变化会重新计时，关闭开关会取消挂起的保存；`Ctrl+S`、页面隐藏（`visibilitychange`/`pagehide`）与渲染器销毁结算不受该开关影响，始终立即保存。
- 结算边界：应用层在会释放仓库或换掉画布的边界先结算当前画板，避免最后一次编辑落在已经释放的仓库上；切换作品/画板时旧画板的改动只需交给后台队列（见上节），不阻塞切换。真正退出时原生端先发 `app_shutdown_requested`，前端在设置页「关闭时保存」开关（默认开启）开启时经 `preparePinBoardRuntimeChange`（`lifecycle.ts`）结算当前画板并 `flushPendingSettle` 清空后台队列，无论成败都调用 `confirm_app_shutdown` 确认，webview 挂起或崩溃时由原生端 15 秒兜底强退；切换仓库时在 `saveSettings` 之前同样先 `await preparePinBoardRuntimeChange()`，当前画板结算失败或后台队列没清空都中止切换并保留旧仓库。生命周期细节见 `docs/architecture/overview.md`。
- 撤销历史只存在于当前会话内存，重开画板后不能撤销。
- 图层由 `layer` 与 `sort_order` 共同决定：图片与文字共用底层/中层/顶层（0–2），笔迹固定占标注层（3，永不与它们混层）；新图片统一进入中层并占据最优先顺序；
- 阵列排序（`src-tauri/src/pin_board/arrange.rs`，整理与导入落位共用同一份实现）：只处理位图条目，文字条目不参与——它的四边形被拉伸时 `fontSize` 不会跟着变，字会被拉变形。算法分四步，顺序只定一次、之后不再改写：统一高度取参与图片原始高度的中位数 → 阅读序（按 y 从高到低分带，带内按 x）→ 动态规划断行（最小化各行宽度与目标行宽的偏差）→ 逐行居中并按裁剪后的外框中心平移回原位。目标行数 `round(sqrt(张数 / 长宽比))` 夹到 `1..=张数`，长宽比取图片中心按名次剔除两端各 10% 后的区间，因此一字排会排成一行、竖列会排成一列，单张离群图既不改变整体形状、也不会把整块拽向自己。间距按「统一高度的比例」计算（设置项 `arrangementGapRatio`，默认 6%，范围 0–20%，`0` 表示图片紧贴），与画布缩放无关；旧实现用屏幕像素换算间距、并在断行之后按宽度对行内与行间各做了一次排序，会把用户摆好的相对位置打乱，已移除。整理的计算经纯计算命令 `arrange_pin_board_images` 完成，前端拿到位置后仍走 `commitMutation`，撤销栈与脏标记不变；
- 拖放导入：把图片文件拖到画布区（`.pin-board-stage`）即可导入，放置点对齐鼠标落点，多张一起拖入时按前一张的显示宽度加一个与图高成比例的间距（与阵列间距同一口径）向右排开；悬停时只描一圈渐变边并在底部显示小胶囊提示，不遮盖画布内容。窗口以 `dragDropEnabled: false` 运行（Windows 上使用 HTML5 拖放的前提），因此 webview **不暴露文件系统路径**，导入走 `import_pin_board_clipboard_image` 的字节链路，只接受可被内容嗅探识别的位图（PNG/JPEG/WebP/BMP/GIF）；需要路径的 DDS/TGA 仍通过「导入图片」选择器处理。画板锁定时不导入并提示；
- Ctrl+A 全选**整个画板**（全部未删除图片，不限视口），实现为 `renderer.selectAll()`；选中态属于视图状态，因此不调整图片顺序、也不标记 dirty，锁定时不生效；
- 加选与框选：`Ctrl`/`Cmd` 或 `Shift` 都是加选修饰键（`selection.isAdditiveSelectionModifier`）。按住修饰键点击图片切换单张选中；在空白处拖拽做框选，按住修饰键时以当前选中为基底累加——可连续多次框选，已选中的不取消、框到的新图加入，不按修饰键则替换选择。命中由 `selection.marqueeSelection` 计算，笔迹按墨迹判、位图与文字按四角框判（见「点选与框选的命中」），只并入命中的未删除条目；拖拽中若选中集合未变（`selection.sameSelection`），只更新框选矩形叠加层，跳过重排、重绘与状态广播；
- Shift 旋转吸附图片的**绝对角度**（0°/15°/30°…，由 `geometry.snapRotationDelta` 反推增量），而非本次拖拽的增量，使已带偏角的图片能被精确转回 0°；
- “添加文字”创建 `kind = text` 条目：前端用 `textLayout.ts` 的固定字体族度量逻辑宽高并持久化，渲染器按请求长边（受纹理像素预算约束）用同一套度量在 2D canvas 栅格化后上传纹理；缩放只改变四边形，文字随四边形精确缩放。栅格化按字形墨迹（`actualBoundingBoxAscent/Descent`）把文字块在每个 1.3 倍行盒内垂直居中，并以此定位基线——此前用 `textBaseline = "top"` 把行高余量全留在下方，文字因此整体偏上、顶部越出纹理被裁掉；显示纹理走这条绘制路径（单条导出已删除，不再有第二条栅格化路径），存量条目也会按新定位重绘。对话框提供内容预览、字号步进与内置取色器（饱和度/亮度面板、色相条、十六进制输入和预设色），不再调用系统取色器。文字条目没有 DDS，也不参与 DDS 引用、清理、scrub、磁盘空间统计；**文字的单条导出已删除**（阶段 2 的整画布导出会一并覆盖文字，不必前端另栅格化一份独立 PNG），系统剪贴板复制也只支持位图。文字条目仍可参与画板内复制/粘贴；
- 笔迹条目（`kind = stroke`）已能画、能读、能选中：几何契约由 `stroke.rs` / `strokeGeometry.ts` 两侧持有，`create_pin_board_stroke` 与 `read_pin_board_strokes` 已可用，渲染走 `strokeRender.ts` 的 SDF 管线（见「渲染」），绘制交互与工具条见「绘制」，选中、移动、旋转、缩放、翻转、删除与撤销复用图片的条目路径；笔迹固定在标注层，右键菜单的「图层」项在选中含笔迹时置灰（原生端保存时也强制写 3），不会产生「改完重开又回去」的状态。四个图层的可见性开关见「图层可见性」。压感、采样光滑、逐段裁剪与开发期自检入口已随阶段 5 落地（见「绘制」与「快速验证」）；发布前的
  `manual` 档压力测试按 `docs/guides/release-policy.md` 由维护者在正式发布前运行；
- 打开画板按未删除图片的最小包围框自动适配视图；“重置视图”回到该包围框；
- 全屏为窗口状态：模块在挂载时与原生全屏标志对齐，Escape 与全屏快捷键只在模块活跃时生效；
- 锁定与全屏快捷键默认为 `Ctrl+R` 与 `F11`，可在设置弹窗“素材板”页自定义（沿用 Client 的快捷键录入控件）；F5 / `Ctrl+R` 整页刷新由应用层的 `preventWebViewReload` 只取消默认行为来屏蔽，不停止事件传播，因此 `Ctrl+R` 仍能命中锁定快捷键，避免 WebView 刷新丢失画布状态（与 Client 的实现一致）；设置 v1 中仍是旧默认值的 `CommandOrControl+Shift+K` 在读取时迁移为 `CommandOrControl+R`（见 `docs/architecture/overview.md`）；
- 画板列表为空或未选中画板时，画布区域显示“当前未选择素材板”等占位提示，不显示加载动画；
- 纹理未就绪的占位：画布上可见、但**缩略图与高清纹理都尚未就绪**的图片，会在其显示范围上铺一块中性灰方框（DOM 层 `.pin-board-placeholder-layer`，由 `renderer.updatePlaceholderOverlay` 按世界→屏幕变换定位），中心是旋转的强调色弧线图标；方框随平移/缩放/旋转同步，图标反向抵消图片角度保持竖直，并随方框缩放（任一边小于 18px 时只留底色）。纹理到位后由下一次 `draw()` 自动移除；节点按 `itemId` 复用，画板释放与 `destroy()` 时清理。加载失败的图片（`failedTextureDimensions` 有记录）改显**红色调**方框与静态 `!` 徽标，不再无限转圈。占位层 `pointer-events: none`，不影响拖拽、框选与拖入导入；缺失 DDS 的图片（`available: false`）不在可见集内，因此不显示占位（仍由工具栏「N 张缺失」提示）；
- 侧栏画板支持拖放排序（沿用 Client 的拖放语义）：拖动行到目标行的上/下半区决定插入到前/后，落库前先本地乐观重排，失败回滚；`reorder_pin_boards` 要求传入的 id 集合与当前未删除画板完全一致（缺项、重复或跨作品 id 一律拒绝），顺序只是列表元数据，不影响已打开画板的编辑会话；
- 将当前选中画板移入回收站时渲染器不销毁，只以「跳过旧画板结算」的方式切换：有回退画板时 `loadBoard(..., stagePrevious=false)`，无可回退画板时 `unloadBoard(false)`；已删除的画板不再暂存快照，避免时序上的写库失败。
