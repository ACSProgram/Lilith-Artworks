## 发布状态

分支必须先有一个 head 才能进入发布状态。用户选择最终成品后，应用工作流在统一备份运行锁内完成以下步骤：

1. 把当前 head 物化并标记为强制检查点。
2. 流式复制最终成品到临时文件，同步并计算 SHA-256；正式发布前先在 `pending_file_cleanup` 登记带哈希的仓库文件意图。
3. 以不覆盖方式发布文件，在事务中确认 head 未变化、插入唯一 `final_artifacts` 行，并原子移除清理意图；中途失败或进程退出时由清理队列回收孤儿文件。

最终成品存在后分支停止提交和自动调度，历史中的发布节点不能被删除或精简。用户可在二次确认后解除发布状态；命令在统一运行锁和 SQLite 事务内登记仓库内最终成品与认证副本的待清理项，删除认证记录和该分支保存的认证配置，再解除分支发布元数据。首次导出的 JPG 属于用户发布产物，始终保留在原路径。仓库文件清理失败项保留并返回 UI 重试，之后分支恢复提交和调度。

## C2PA 与 TrustMark

C2PA 是每次认证导出的强制基础，不能关闭。发布版固定输出 JPEG，并包含：

- `com.lilith.artworks.claim` 自定义声明；
- `stds.schema-org.CreativeWork`；
- 最终成品的 `parentOf` ingredient；
- `c2pa.transcoded` action；
- 启用 TrustMark 时的 `c2pa.soft-binding` 和 `c2pa.watermarked` action。

TrustMark 可关闭。启用时使用 Q/BCH_SUPER 模型和 40 位二进制 ID，只在用户框选的最多 8 个矩形区域内嵌入，强度范围为 0.50 到 1.50；没有框选区域时自动降级为仅 C2PA。模型文件不可用时 UI 也强制降级为仅 C2PA。模型变体和编码/解码模型 SHA-256 由后端读取后显示，不在前端写死。私钥只存在于单次命令内并用 `Zeroizing` 包装，不写入配置、数据库、localStorage 或日志。

签名流程先在目标目录生成临时 JPEG，再写 C2PA 并回读验证。只有回读到 manifest 后才计算哈希并登记外部输出与仓库副本的清理意图；两个文件都以不覆盖方式发布，`certification_records` 事务提交时原子移除意图。数据库失败、文件步骤失败或进程中断留下的文件由队列立即清理或在下次启动时重试。

正式签名前必须先生成质量预览。预览从仓库内最终成品重新执行与发布相同的透明背景合成、TrustMark 区域编码和 JPEG 质量编码，完整 JPEG 直接写入自动删除的临时文件以取得真实输出大小，IPC 只返回最长边不超过 2400 px 的导出缩略图和原图缩略图作为基础层与首屏。界面显示原始像素尺寸，缩放以源像素为基准（100% 即一个源像素对屏幕上的一个 CSS 像素），缩略图只是放大前的底图；只要缩略图被放大（显示尺寸超过缩略图本身），界面就通过 `preview_authenticity_tile` 按可视区域向源分辨率请求高清局部：`source` 为 `compressed` 时裁剪缓存的无签名 JPEG（令牌格式、矩形范围与解码资源预算都在后端校验），为 `original` 时按分支解析受控成品路径裁剪仓库最终成品。裁剪块只缩不放，输出边长按局部在屏幕上的显示尺寸给出（上限 4096 px），因此放大后是真正的 1:1 源像素，而不是插值放大的缩略图；局部统一编码为无损 PNG，因为预览的用途就是观察 JPEG 与 TrustMark 造成的损失，若再按有损 JPEG 回写一次，界面会叠加并非成品本身带来的压缩痕迹。局部去抖后叠加在基础缩略图上，按「来源 + 矩形 + 分辨率」做客户端缓存（上限 12 块），并且只有与当前对位一致的局部图才会渲染。缩略图未被放大时直接显示缩略图就已经是 1:1 或更好，不请求局部。读取前必须先把文件 SHA-256 与 `final_artifacts.source_sha256` 对照。C2PA 只写元数据且不重新编码像素，因此在用户确认并选择输出路径后才执行。自动生成的 TrustMark ID 会随预览回填，后续正式发布复用同一 ID；该 ID 只属于当前分支的一次待发布操作，切换分支、关闭 TrustMark 或发布成功后立即清空。

质量预览会在当前进程的仓库 `temp/authenticity-preview-<session>/` 会话目录缓存无签名 JPEG，并返回缓存 token 与渲染/编码耗时。token 由最终成品 SHA-256、分支和全部像素影响参数、TrustMark ID 绑定；发布命令只有在 token、缓存元数据、JPEG 摘要/尺寸和最终成品 SHA-256 全部重新核验通过时才复用，否则删除失效缓存并回退重算。缓存不作为仓库记录或外部输出，签名失败时不会被当作成品发布。发布结果另外返回无签名成品是否命中缓存、重算耗时和 C2PA/时间戳签名耗时，供界面显示阶段状态与诊断信息。

质量预览和签名发布共享单一认证活动任务；前端可通过 `cancel_authenticity_operation` 请求取消，切换分支或离开发布页也会请求取消旧任务。质量预览运行时显示独立的“正在生成”状态和取消动作，手动取消只有在任务实际以取消结果结束后才通过全局操作提示报告“质量预览已取消”，不会把刚发出的请求或正常完成误报为已取消。图像打开、缩略图、背景合成、TrustMark、JPEG 编码、缓存发布、C2PA 签名、回读和摘要之间都检查取消；TrustMark 推理、单次图片编解码和 C2PA SDK 的本地调用无法在函数内部强制中断，因此取消延迟取决于当前阶段，并在下一边界生效。取消发生在缓存发布前时不留下缓存文件，发生在外部输出发布前时由临时目录自动清理；一旦清理意图已提交并开始原子发布，流程会完成数据库收尾或既有失败恢复，不在中间中断。

RFC 3161 时间戳请求使用无重定向客户端，单次硬超时为 30 秒；等待期间每 100 ms 检查取消。取消后签名命令立即停止等待，独立网络请求最多继续到自身 30 秒超时，但不持有私钥且不能发布文件或写入记录。未配置时间戳 URL 时不启动网络请求。

所有认证图像在真正解码前先读取图片头并统一检查资源预算：单边最多 32768 px、总像素最多 300 MP，解码器同时分配预算为 1.5 GiB；16K 图像约 268 MP，属于允许范围。不按压缩文件字节数拒绝输入，因此 100 MB 以上的正常图片不会仅因文件大而失败。普通发布、记录与识别预览只通过 IPC 返回最长边 1600 px 的 PNG 缩略图。透明背景合成直接遍历源像素，不再额外生成一份全图 RGBA；完成合成后立即释放源解码图，大小预估使用计数写入器而不保留完整 JPEG 字节。工作区只挂载当前活动的历史、发布或识别页面，离开页面会释放对应 controller、base64 和浏览器解码图。

## 导出记录与识别

候选版仅支持 ES256、ES384 和 Ed25519 C2PA 签名。PS256 因 `c2pa` 原生加密依赖链中的 `rsa` 安全公告被同时从界面与后端校验中禁用；绕过界面提交原生命令也会在读取签名材料前被拒绝。

每条导出记录固定关联分支、发布节点和最终成品，保存时间、首次输出路径、仓库内认证 JPG 副本、大小/SHA-256、内容声明、TrustMark ID、范围 JSON、C2PA manifest JSON 和验证状态。记录 ID 在签名前生成，并始终写入 `com.lilith.artworks.claim.recordId`；因此关闭 TrustMark 的仅 C2PA 发布也能稳定回查本地记录。所有记录必须有仓库副本，查看和再次导出只读取该副本并先核对 `output_sha256`，不依赖首次输出路径；缺失、损坏或被替换时明确拒绝。再次导出在后端使用不覆盖发布，目标已存在时明确拒绝。记录可按 ID、标题、创作者或首次输出路径搜索。

单条记录可以在记录查看页的“更多记录操作”菜单中通过“删除本记录”删除，经应用内二次确认后由 `delete_certification_record` 执行：命令先解析记录所属分支并取得独占运行锁，在事务内为仓库副本登记带哈希的清理意图，再删除记录行并立即执行清理；哈希不匹配等清理失败会进入共享待清理队列并在界面提供重试。首次导出的 JPG 始终保留在原路径。删除记录不影响分支发布状态与最终成品；分支的全部记录仍只能通过“取消发布并删除本地数据”整体清除。

签名完成后的回读采用 fail closed：必须存在 active manifest，验证状态必须是 `Valid` 或 `Trusted`，并逐项核对本次 record ID、TrustMark ID（启用时）、标题、创作者、权利声明和认证内容，任一不匹配都不会发布或写入记录。设置页全库完整性扫描会对已有认证仓库副本重复 SHA-256、C2PA 验证状态和数据库声明核对。

`src-tauri/tests/fixtures/authenticity/` 保存约 41 KB 的公开测试专用 ES256 凭据、128 x 128 源图、真实 C2PA/TrustMark 签名图和覆盖字节被篡改的签名图。定向 Rust 测试使用生产回读、TrustMark 模型解码与发布校验函数，固定覆盖合格状态、像素水印与 C2PA 中的 record ID/TrustMark ID/全部声明匹配，以及文件替换、C2PA 无效状态和声明不匹配的 fail-closed 行为；fixture 私钥不得用于生产。

识别始终读取 C2PA；模型可用时还会对整图或用户框选区域解码 TrustMark。候选匹配分别使用 C2PA `recordId` 与解码出的 TrustMark ID 查询全库索引；旧 C2PA 记录没有 `recordId` 时回退使用声明中的 TrustMark ID。两组结果按记录 ID 去重并保留 `c2pa` / `trustmark` 证据来源，冲突时同时显示两个通道的候选，不把任一候选自动判为可信。点击候选会切换到所属 Artwork、发布分支并高亮具体导出记录。模型解码本身不等于真实性认证，必须结合 C2PA 验证状态和本地记录判断。

## 数据版本

认证记录的 `stored_path` 为非空约束，每条记录都必须有仓库内 JPG 副本；DTO 和界面不暴露冗余的 `contentStored` 状态。共享待清理队列处理发布创建失败和取消发布的数据库/文件边界；取消发布只清理仓库拥有的文件，不清理首次导出路径。

## 前端交互约定

- Authenticity 不直接导入 App、Library 或 History。应用层传入只含 `id`、`title`、`headHistoryId` 的认证分支视图，注入清理重试，并把认证记录转换为 Library 导航目标。
- `useAuthenticityController.ts` 是 `authenticity/api.ts` 的唯一消费者；发布页和识别页只渲染控制器状态。发布状态、成品预览、记录预览、大小估算、识别和记录搜索分别使用请求代次，分支或输入变化后旧响应不会回填当前页面。
- 当前分支由 `ArtworkWorkspace` 统一持有；历史页和发布页共用同一选择，任一页面切换分支都会同步到另一页面。发布、进入发布和取消发布后刷新 Artwork 工作区分支数据，发布状态与当前内容保持同步。识别/搜索结果跳转携带单调递增的导航代次；即使目标仍是同一 Artwork 或同一记录，也会重新切到发布页并选择目标分支，同时保留已经加载的分支列表。
- 发布元数据、成品预览和大小估算使用各自的 latest-request-wins 请求代次；分支切换后旧请求不得覆盖新分支状态。发布元数据成功后立即进入已发布视图，成品预览独立加载和重试；预览缺失、损坏或被替换时不得隐藏发布状态、导出记录或取消发布入口。发布命令发出前再次确认当前选择、配置、最终成品和已加载发布状态属于同一分支。
- PEM 私钥仅以密码输入控件接收，并且发布完成后清空，不写入共享配置。
- 发布命令先按正式编码参数生成质量预览缩略图；预览层提供返回调参和直接签名发布，参数改变后再次生成会替换旧预览。
- TrustMark 仅在存在框选区域时启用；首次完成框选自动启用，清空全部区域自动关闭。
- JPG 质量、预估大小和透明背景色位于 TrustMark 之前；TrustMark 区明确提示在左侧图片拖动框选区域，避免把开关误解为唯一入口。
- 点击导出记录进入只读查看模式。查看页复用发布编辑页的左右分栏和图片预览结构，显示锁定字段、框选范围、发布节点、文件摘要和 C2PA 报告，并提供再次导出、删除记录和明确的退出入口；任何认证参数均不可编辑。删除记录收纳在“退出查看”右侧“更多记录操作”二级菜单中，菜单项为“删除本记录”，使用应用内二次确认，成功后退出查看并刷新分支记录列表。
- “取消发布并删除本地数据”收纳在页头“更多发布操作”二级菜单，并使用应用内二次确认；确认后删除仓库内最终成品、全部认证记录、仓库副本和保存配置，但保留记录指向的首次导出文件。
- 识别区域支持撤销并恢复整图识别；识别结果继续提供匹配记录与记录搜索。
- 识别页支持把外部图片拖入左侧预览面板导入：前端用 `FileReader` 读取原始字节，经 `stage_authenticity_input` 落到系统临时目录（仓库之外）并加入 filesystem scope，再走与文件选择器相同的外部图片预览与识别流程；只接受 PNG、JPEG、WebP、TIFF，拖放失败以统一操作提示报告，拖放期间显示覆盖提示。应用层统一取消窗口级 `dragover`/`drop` 默认行为，避免拖入文件时 WebView 导航到该文件。
- 图片预览、识别和记录搜索均使用独立请求序号丢弃乱序响应；识别 busy 与记录搜索 busy 独立，后台搜索不会解除或阻塞正在进行的图片识别。
- 发布预览和识别预览的文件标题栏使用固定内容高度，图片舞台独占剩余空间；超大分辨率图片不能拉高标题栏。
- 只读记录中的输出路径、Manifest 标签和 SHA-256 允许完整换行，不用省略号隐藏校验信息；窄布局下危险区改为纵向排列，长 Artwork 标题在操作按钮前省略。
- 警告文本使用主题变量，在浅色与深色主题分别保持可读对比度。
- 框选坐标只相对 `object-fit: contain` 后的实际图片矩形归一化；舞台留黑不进入坐标。图片显示矩形由 `ResizeObserver` 随窗口尺寸同步更新，标签禁用文本选择。识别页开始新拖动时立即清除唯一旧框，并在有效拖动完成后写入新框。
- PEM 私钥非空检查在生成质量预览时进入统一操作提示，不常驻显示独立警告行，也不因输入为空而禁用预览按钮。
- 质量预览生成前先检查标题、创作者、证书链和 PEM 私钥；图片超出视口时显示导航小图，可点击或拖动视口框快速定位。
- 质量预览没有独立的“适应”模式：缩放始终是数值且以源像素为基准（显示尺寸 = 源像素 × 倍率，100% 即 1:1），初始值由画布尺寸与源图尺寸算出的适应倍率决定（画布尺寸尚未测得时退化为 1），画布拖拽从打开预览起即可用；普通滚轮用原生非被动监听按滚轮增量平滑缩放（鼠标滚轮约 10%/格，触控板保留更细粒度），工具栏按钮按 10% 比例步进；缩放时保持鼠标指向的图像位置，放大后通过画布拖拽或导航小图定位，不显示滚动条。“适应窗口”只把数值缩放重置回当前适应倍率，并在画布尺寸变化时自动跟随。
- 质量预览在导出图和原始成品之间切换时保留当前数值倍率，允许在放大状态下往返对比同一位置。
- 质量预览的高清局部只在缩略图被放大时请求（显示尺寸超过缩略图本身；缩略图未被放大时直接显示缩略图即为 1:1 或更好）：矩形按当前可视区域换算到源像素并带 25% 边距，起点向下吸附、终点向上吸附到「可视跨度 × 25%」的格宽（吸附后的矩形一定仍覆盖可视区域），因此小幅平移落在同一格内、复用同一块局部而不是每移动一个像素就重新请求；`maxEdge` 取局部在屏幕上的显示尺寸（上限 4096 px）让后端把裁剪块缩放到正好一源像素对一屏幕像素，去抖 180 ms 后请求，响应按请求代次丢弃、结果按「来源 + 矩形 + 分辨率」缓存（上限 12 块）。局部图按源矩形百分比叠加在缩略图上，定位必须通过内联 `style` 下发（把定位对象当作 props 展开会让它退回静态位置、掉到基础图下方）；只有 key 与当前对位一致的局部图才渲染，因此平移或缩放时不会残留错位的旧局部图，切换导出图/原图时按来源区分，请求失败静默回退到缩略图。签名发布进行中不发起新请求，但保留已加载的局部图。
- 仓库最终成品预览和大小估算只接收分支 ID，由后端解析受控路径；发布与再次导出目标拒绝仓库内部路径。文件选择器打开的最终成品、证书、外部预览/识别图片和输出目标会进入临时 filesystem scope；拖入的待识别图片由 `stage_authenticity_input` 落到系统临时目录后同样加入 scope，因此后续预览与识别仍走同一条授权检查。原生命令同时核验 scope 和仓库边界；应用重启后 scope 清空，证书等外部路径必须重新选择。filesystem 插件未向前端授予读写命令权限。
- 路径授权来源（`authenticity::ensure_dialog_authorized` 的 scope 参数）是**可注入的**：GUI 侧实现是 `window.fs_scope()`，开发/验证期的无头入口实现是一个只允许工作区之内路径的显式作用域。两条实现都要求路径被显式授权、都拒绝空路径，不存在可关闭该检查的开关；GUI 侧的判断与文案与重构前逐位一致。

## 可靠性不变量与覆盖

认证模块的安全边界与可靠性承诺，由发布前的自动化压力测试（`stress_authenticity`，**发布前手动运行、
不进 CI**，见 `docs/guides/validation.md` 与 `docs/guides/stress-test-report.md`）以独立进程调用
真实可执行文件验证：

| 不变量 | 证明场景 |
| --- | --- |
| 16K 源图（16384×16384，约 2.68 亿像素）的解码 + TrustMark 编码 + C2PA 签名峰值内存不超出声明的 1.5 GiB 解码预算量级；渲染 / 编码 / 签名各阶段耗时被记录，无超时与挂起 | G1、G2 |
| 渲染 / 编码 / 签名任一阶段取消都不留下半成品：无输出文件、输出目录无残留临时产物、认证记录数为 0；`cancel-publication` 后仓库内成品与记录被清除，仓库重开可用 | G3 |
| `decode-authenticity` 能读回 C2PA 声明（record ID、标题、创作者、权利声明）与 TrustMark 绑定并与本地记录一致，候选带 `c2pa` + `trustmark` 两条证据 | G4 |
| `scrub` 覆盖最终成品与认证仓库副本的摘要比对：替换副本字节后校验失败（「已损坏或被替换」），证明是真实比对而非计数 | G5 |
| 路径授权来源可注入，但两条实现都要求路径被显式授权、都拒绝空路径，不存在可关闭该检查的开关；无头进程只授权工作区之内的路径 | 复用同一条检查（`ensure_dialog_authorized`） |
